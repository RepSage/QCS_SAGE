# QCS v8.0 — Doppler current-profiler (DCPS): qualification + visualization

> **MAJOR** release (v7.0 → v8.0), developed on branch `improvements-v8.0`.
> MAJOR because an entirely new data family enters qualification: the Aanderaa
> DCPS current profiler that v7.0 archived-but-skipped is now decoded, quality
> controlled and plotted through its own pipeline.
> Note: the version bump resets saved QC criteria to the defaults on first
> launch, per the version-gated settings rule.

## The DCPS raw binary format — decoded and validated

The DCPS sessions use the same AADIBXML container as the scalar SeaGuard
sessions, but a much richer record. The reverse-engineered rules
(`_parse_aadi_dictionary`, `_decode_dcps_bin` in `QCS_DataHandler`):

- The tag dictionary is parsed **sequentially** (13-byte prefix, name, NUL,
  3 zero bytes per entry); the regex scan used for scalar files corrupts on
  dictionaries this large.
- Value slots are the template `<Point>`s that **contain** a `<Value/>`. The
  self-closing Points inside `<CellAttributes>` only define the per-cell
  parameters (ID → name/unit); each `<Cell>` holds bare Points referencing
  them. The k-th Point-parented dictionary `Value` ↔ the k-th slot.
- Value payloads are typed: float32/int32 (4 B) and **int16 (2 B)** — Air
  Detect, Ping Count, Cell States. The `<Vector>` element (EventReg flags) is
  an array: element-count prefix + count × int32. **The prefix is u32 on most
  deployments but u16 on some (same type code)** — the width is auto-detected
  per file by requiring each record walk to land exactly on the record
  boundary.
- `rec_len` counts from the SYNC marker and each record ends with a 4-char
  checksum, so records are walked by bytes; a record that does not land
  exactly on the boundary is rejected, never half-read.
- **Validated against the instrument's own CSV export** (CFRIO1 22.03.2021):
  15,948 value comparisons across 12 aligned records — 100% of the measurement
  parameters identical (the only differences are fields the CSV itself leaves
  blank).

## Current qualification (per depth cell)

`read_seaguard_doppler` produces a tidy frame — one row per record × depth
cell (`Datetime`, `Column`, `Cell`, `Depth (m)` = ColumnStart +
CellSize×(cell+0.5), horizontal/north/east/vertical speeds, direction, speed
stdev, signal strength, cell state, plus the record attitude: heading, pitch,
roll, tilt, ping count). `QCS_Tests.doppler_qc` then writes a 4-character flag
string per row (same architecture as the scalar flag string) and a `Flag_cur`
roll-up (4 > 3 > 9 > 1):

1. **Current speed range** — magnitude below 0 or above 300 cm/s → BAD.
2. **Signal quality** — cell state ≠ 0 (out of range / no echo), return
   strength below the −60 dB noise floor, **or strength ≥ 0 dB** (genuine
   echoes are always negative; exactly 0.0 is the instrument's "no ping"
   placeholder) → BAD.
3. **Speed standard deviation** — single-ping stdev above 50 cm/s → SUSPECT.
4. **Instrument tilt** — above 15° SUSPECT, above 35° BAD (tilt compromises
   the whole record).

Defaults live in `QCS_Tests.DOPPLER_DEFAULTS` (exposing them in the Settings
window is a candidate follow-up).

## Current visualization

`QCS_DataView.plot_doppler_panels` renders 4 panels (BAD rows excluded):
time×depth heatmaps (speed + direction), a stick plot at the best-covered
depth, U/V component series at up to 4 depths, and a progressive vector
diagram.

## App integration — the 'TSCP Doppler' data type

- **Qualification**: the Data type combobox gains **`TSCP Doppler`**. Browsing
  a DCPS `.bin` auto-sets it (`is_seaguard_doppler`); picking a scalar session
  while it is selected falls back to `TSCP Mooring`. Choosing `TSCP Doppler`
  for a non-DCPS file raises a clear error. The pipeline: read → optional
  GMT-3 → current QC → `<session>_DOPPLER_QLF\QCS qualified current
  data\<name>` (+ flag legend) → `QCS DataView (current)\` (the 4 panels).
  The qualified current table carries a **`Site` column** and is
  **comma-separated** like every other QCS sheet.
- **Visualization**: the Instrument combobox gains **`Doppler`**
  (auto-detected from the selected file via `detect_qualified_layout`), the
  Data type shows **`TSCP Doppler`**, and *Generate panels* renders the 4
  current panels into `<output>\DatabaseView\<site> (current)\` for each
  selected site/year — the same standard output folder as the scalar panels.
  `build_database` accepts the `Doppler` instrument (subfolder
  `QCS qualified current data`) and refuses mixing Doppler with HOBO/Seaguard
  sheets, like the other layouts.
- The scalar pipeline is untouched; a DCPS group whose profile output was
  disabled (attitude-only, no cells) raises a clear message.

## Autonomous bug-hunt (agents over all 61 real DCPS deployments)

The headless harness drove the real pipeline over every DCPS session in the
staged corpus; findings were adversarially re-verified. Two real defects were
found and fixed:

- **Vector element-count width** (above): the u32-only read crashed whole
  files ("no data records found" — PONTO 19 CANAL 2024 = 4 days of records;
  SGOMES 2024; RODORASO 2020) and silently dropped 0–43% of records in many
  more (worse: an overshooting walk could keep records with corrupted tails).
  With the per-file auto-detection: BURACAS 98→309 records, RH50 64→112,
  SGOMES crash→322, PONTO 19 crash→196; CFRIO1 unchanged (validated values).
- **"No ping" placeholders passed as GOOD**: rows with strength exactly
  0.0 dB, cell state 0 and all-zero speeds are instrument placeholders, not
  measurements (605 of BURACAS's 618 GOOD rows). The signal-quality test now
  fails on strength ≥ 0.

## HOBO reader — the whole corpus reads (98% → then 99% with optional light)

Batch-qualifying the archive exposed reader gaps that silently blocked nearly
half of the 232 HOBO exports; all fixed and measured over the real corpus
(230/232 readable — the 2 left are malformed inputs needing re-export):

- **pt-locale clock + month-first dates**: exports write `04h0min0s` and
  roughly half carry month-first dates; the fixed `dayfirst=True` parse turned
  every row into NaT. The clock is normalized and the day/month order is
  decided from evidence in the data (a value > 12 in the second field can only
  be the day); day-first stays the default when ambiguous.
- **Date and time in separate columns** (`Data` + `Hora, GMT-03:00`), including
  exports that repeat the whole stamp in both.
- **Deployment window could delete the deployment**: when the coupler was
  first touched at READOUT, all logger events sit at the end of the record and
  the implied window kept ~0 rows (PAB3 2018–19: 13 months discarded). The
  window is now applied only when it keeps most of the measurements.
- **Light channel is OPTIONAL**: temperature-only Pendant loggers qualify
  normally (Luminosity empty, light tests not evaluated, `Flag_lux` = 9);
  recovers e.g. 2 years of PAB3 wall temperature (2016–2018).

## Visualization fixes (found by rendering real panels)

- **Doppler stick plot** was unreadable: the quiver mixed cm/s with date-axis
  units (sticks ~40 days wide). Now angle-true, scaled independently of the
  time axis, with a reference key — and NaN-safe (fully-missing rows, flagged
  9999, no longer crash the vector panels after panel 1).
- **T-S diagram** axis was stretched to 0–36 PSU by out-of-water salinity
  spikes; the envelope now comes from GOOD-flagged rows only (0.5% trim,
  minimum window so near-constant moorings keep a valid contour grid).
  Suspect/bad points are still plotted; they just no longer set the view.
- **Profile panel (panel3)** sizes its figure to the parameter count — the
  stacked per-parameter x-axes no longer overflow and vanish with 10+
  parameters selected.
- Panel titles show "1st semester" (was "1stSemester").

## Site Code up to 20 characters

The 10-character cap rejected the corpus's descriptive site names
(`PISCINA_PLES_DENTRO`, `BORDA_SUL_ABROLHOS`, …). The cap is now the named
constant `SITE_CODE_MAX = 20` (validation + tooltip + manual).

## Audit fixes

- **Progressive vector diagram invented displacement across gaps.** The series
  it integrates is not continuous (BAD cells are dropped; the Visualization
  renders every selected year in one set), so speed × elapsed-time across a gap
  fabricated a trajectory: two clean 1-day blocks 30 days apart produced a
  133.9 km plot where the real displacement is 8.6 km — and the SVG looked
  valid. Gaps (> 3× the median step) are no longer integrated and break the
  line; the title reports how many were skipped; panel dates now carry the year.
- **Ambiguous HOBO dates are now flagged.** When neither date field ever exceeds
  12, nothing proves day-first vs month-first and a wrong guess silently moves
  every sample to another month. Measured first: 0 of 232 exports are ambiguous,
  34 are proven month-first, 0 proven day-first — so this guards future files
  (and records that day-first, the legacy default, is not what these exports do).
- **Split date/time join** no longer poisons the stamp when the hour column is
  datetime-typed (`astype(str)` kept its own `1899-12-31` date).
- **A CO2 file picked together with a DCPS session** was dropped in silence; it
  is now logged (the current pipeline has no scalar series to merge onto).
