## The DCPS raw binary format — decoded and validated

The DCPS sessions use the same AADIBXML container as the scalar SeaGuard
sessions, but a much richer record. The reverse-engineered rules
(`_parse_aadi_dictionary`, `_decode_dcps_bin` in `QCS_DataHandler`):

- The tag dictionary is parsed **sequentially** (13-byte prefix, name, NUL,
  3 zero bytes per entry); the regex scan used for scalar files corrupts on
  dictionaries this large.
- Value slots are the template `<Point>`s that **contain** a `<Value/>`. The
  self-closing Points inside `<CellAttributes>` only define the per-cell
  parameters (ID → name/unit); each `<Cell>` holds bare Points referencing
  them. The k-th Point-parented dictionary `Value` ↔ the k-th slot.
- Value payloads are typed: float32/int32 (4 B) and **int16 (2 B)** — Air
  Detect, Ping Count, Cell States. The `<Vector>` element (EventReg flags) is
  an array: element-count prefix + count × int32. **The prefix is u32 on most
  deployments but u16 on some (same type code)** — the width is auto-detected
  per file by requiring each record walk to land exactly on the record
  boundary.
- `rec_len` counts from the SYNC marker and each record ends with a 4-char
  checksum, so records are walked by bytes; a record that does not land
  exactly on the boundary is rejected, never half-read.
- **Validated against the instrument's own CSV export** (CFRIO1 22.03.2021):
  15,948 value comparisons across 12 aligned records — 100% of the measurement
  parameters identical (the only differences are fields the CSV itself leaves
  blank).

## Current qualification (per depth cell)

`read_seaguard_doppler` produces a tidy frame — one row per record × depth
cell (`Datetime`, `Column`, `Cell`, `Depth (m)` = ColumnStart +
CellSize×(cell+0.5), horizontal/north/east/vertical speeds, direction, speed
stdev, signal strength, cell state, plus the record attitude: heading, pitch,
roll, tilt, ping count). `QCS_Tests.doppler_qc` then writes a 4-character flag
string per row (same architecture as the scalar flag string) and a `Flag_cur`
roll-up (4 > 3 > 9 > 1):

1. **Current speed range** — magnitude below 0 or above 300 cm/s → BAD.
2. **Signal quality** — cell state ≠ 0 (out of range / no echo), return
   strength below the −60 dB noise floor, **or strength ≥ 0 dB** (genuine
   echoes are always negative; exactly 0.0 is the instrument's "no ping"
   placeholder) → BAD.
3. **Speed standard deviation** — single-ping stdev above 50 cm/s → SUSPECT.
4. **Instrument tilt** — above 15° SUSPECT, above 35° BAD (tilt compromises
   the whole record).

Defaults live in `QCS_Tests.DOPPLER_DEFAULTS` (exposing them in the Settings
window is a candidate follow-up).

## Current visualization

`QCS_DataView.plot_doppler_panels` renders 4 panels (BAD rows excluded):
time×depth heatmaps (speed + direction), a stick plot at the best-covered
depth, U/V component series at up to 4 depths, and a progressive vector
diagram.

## App integration

Selecting a DCPS `.bin` in the normal Seaguard flow **auto-detects** the
current profiler (`is_seaguard_doppler`) and routes to the Doppler pipeline:
read → optional GMT-3 → QC → `<session>_DOPPLER_QLF\QCS qualified current
data\<name>` (+ flag legend) → `QCS current panels\`. The scalar pipeline is
untouched; a DCPS group whose profile output was disabled (attitude-only, no
cells) raises a clear message.

## Autonomous bug-hunt (agents over all 61 real DCPS deployments)

The headless harness drove the real pipeline over every DCPS session in the
staged corpus; findings were adversarially re-verified. Two real defects were
found and fixed:

- **Vector element-count width** (above): the u32-only read crashed whole
  files ("no data records found" — PONTO 19 CANAL 2024 = 4 days of records;
  SGOMES 2024; RODORASO 2020) and silently dropped 0–43% of records in many
  more (worse: an overshooting walk could keep records with corrupted tails).
  With the per-file auto-detection: BURACAS 98→309 records, RH50 64→112,
  SGOMES crash→322, PONTO 19 crash→196; CFRIO1 unchanged (validated values).
- **"No ping" placeholders passed as GOOD**: rows with strength exactly
  0.0 dB, cell state 0 and all-zero speeds are instrument placeholders, not
  measurements (605 of BURACAS's 618 GOOD rows). The signal-quality test now
  fails on strength ≥ 0.
