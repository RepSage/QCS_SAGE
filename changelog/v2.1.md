## 1. MAIN BUG — fixed scale did not work on profiles (Panel 3)
**File:** `QCS_DataView.py` · function `plot_database_panel3` · ~line 757

Inside the loop over the secondary axes (`twiny`), the scale fixing did:

```python
ax1.set_xlim(scaleSettings[parameter_names[i-1]]['min'],
             scaleSettings[parameter_names[-1]]['max'])   # <-- wrong
```

Two errors on the same line:
- **Wrong axis:** it applied to `ax1` (the first axis) instead of `ax`, the `twiny` axis
  that had just been created. The result: the secondary axes never received the fixed
  scale (they stayed on autoscale), and the first axis was overwritten on every
  iteration.
- **Wrong index on the max:** it used `parameter_names[-1]` (the last parameter) instead
  of `parameter_names[i-1]` (the current one) — mixing one parameter's min with another
  parameter's max.

**Fix:**
```python
ax.set_xlim(scaleSettings[parameter_names[i-1]]['min'],
            scaleSettings[parameter_names[i-1]]['max'])
```

Demonstration (synthetic data, fixed ranges deliberately outside the data):

| Axis | Before (buggy) | After (fixed) | Expected |
|------|----------------|---------------|----------|
| Temperature | (30, 50) ← salinity's values | (5, 10) | (5, 10) |
| Salinity | (32.8, 37.0) ← autoscale | (30, 50) | (30, 50) |

Note: profiles with a **single parameter** already worked (they use line ~703, which was
correct); the problem only appeared with **2 or more parameters** in the same profile.
The mooring panels (Panel 1 and Panel 2) were already correct and were validated.

## 2. Robustness — a partially filled scale broke the whole panel
**File:** `QCS_DataView.py` · Panels 1, 2 and 3

`saveDataViewSettings` only writes a parameter into `scaleSettings` when **both min AND
max** are filled in. If a selected parameter was left without min/max, the direct access
`scaleSettings[parameter]` raised `KeyError` and brought down the generation of the whole
panel (it became "ERROR generating Panel X" in the log).

**Fix:** every application of the fixed scale now checks that the key is present before
using it, e.g.:
```python
if dataViewSettings['fixedScale'] and parameter_names[0] in dataViewSettings['scaleSettings']:
    ...
```
Parameters with no range defined simply fall back to autoscale, instead of aborting the
panel.

## 3. Portability — icons never loaded away from the original machine
**Files:** `QCS_DatabaseView.py` (2 occurrences) and `QCS_Main.py` (3 occurrences)

The calls passed a **hardcoded absolute path** to `resource_path`:
```python
resource_path(r"C:\Users\JoaoCardoso\QCS_SAGE_v2.0\sourceCode\qcsMainIcon.ico")
```
Since `resource_path` does `os.path.join(base, path)` and the second argument was
absolute, the join ignored `base` (including PyInstaller's `_MEIPASS`). Away from the
original machine the file did not exist → it fell into the `try/except` → windows with no
icon, silently.

**Fix:** pass only the relative name, which is how `--add-data` packages it:
```python
resource_path("qcsMainIcon.ico")
```

## Recommended items (NOT changed — for your evaluation)

- **Regex in plain strings** (`'\d'`, `'\('`, `'\s'` and so on) in `QCS_Main.py` and
  `QCS_DataHandler.py`: they work under the project's Python 3.8, but they raise a
  `SyntaxWarning` on Python ≥ 3.12 and are expected to become an error in future. The
  recommendation is to prefix them with `r''` (e.g. `r'\d{1,3}'`). The change is
  mechanical, but dozens of lines were left untouched pending your approval.
- **Dead code:** `plot_database_panel2_DEPRECATED` in `QCS_DataView.py` is no longer
  called (the active version is `plot_database_panel2`). It can be removed whenever
  convenient.
