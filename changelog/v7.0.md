# QCS v7.0 — Read every sensor group from the raw SeaGuard session, qualify the deployment together

> **MAJOR** release (v6.0 → v7.0), developed on branch `improvements-v7.0`.
> MAJOR because it changes what data reaches qualification: a previously
> **rejected** binary layout now decodes (unlocking pH / chlorophyll / turbidity /
> CDOM), and a multi-group cast is now merged into ONE record before the QC runs.
> Note: the version bump resets saved QC criteria to the defaults on first
> launch, per the version-gated settings rule.

## Background — how the raw sessions are actually laid out

A SeaGuard cast/deployment is stored as one or more **sensor-group folders** side
by side, named `<serial>-<groupindex>-<start-timestamp>Z` (each with its own
`Data000.bin`). The current standard protocol logs all sensors together in one
synchronous group (plus a separate Doppler group), but many older deployments
split the sensors into **several groups sampled at different rates** over the same
window — e.g. CTD/optode every 2 s, the pH/optical (Analog) group every 10 s, PAR
every 5 s. v6.0 read only the selected folder, so those casts qualified one group
at a time and the pH/optical group did not read at all (see below).

## Reader fix — the pH / chlorophyll / turbidity / CDOM group now decodes

- The AADI template lists each parameter as a `<Point>`. The v6.0 reader counted
  only the `<Point>`s **inside** the `<SensorData>` blocks, but the Analog sensor
  group also carries two device-housekeeping points (`Input Voltage`,
  `Memory Used`) **outside** any `<SensorData>` — which still own a value slot in
  the tag dictionary. The counts disagreed and the reader raised
  *"unsupported layout variant"*, so the whole group (pH, chlorophyll, turbidity,
  colored dissolved organic matter) was unreadable.
- `_decode_aadi_bin` now takes **every `<Point>`** in template document order
  (tolerant to attribute order), matching the k-th dictionary `Value` id to the
  k-th point. The standard T/S/C/P/O2 layouts are unchanged (all their points are
  already inside `<SensorData>`); the previously-rejected groups now decode.
- **Validated on real data**: the pH column reads a seawater median ~7.3–7.9 and
  the housekeeping `Input Voltage` ~7.7 V — i.e. the columns land on the right
  values, not just the right count.

## Deployment merge — a multi-group cast qualifies as one record

- New `read_seaguard_deployment()` (used by `read_ctd` for every `.bin`): from the
  selected group folder it finds the **sibling group folders of the same cast**
  (same instrument serial and start time, within a small tolerance) and reads them
  together.
- Groups sampled at different rates are aligned onto **one time axis**: the
  **finest group** (most records) is the master, and each slower group's parameter
  columns are **linearly interpolated in time** onto the master's `Record Time` —
  the same "common denominator" approach already used for the dissolved-CO2 merge.
  A gap larger than 2× a group's own median interval is not bridged (NaN) and no
  value is extrapolated beyond a group's own coverage. Cross-group column-name
  clashes are kept unique.
- A single-group deployment (the current synchronous protocol) is returned as-is;
  nothing changes for it.

## Doppler / current profiler (DCPS) — archived, not yet qualified

- The Doppler current-profiler groups use a genuinely different template (per-cell
  current arrays: ~100 template points vs ~500 value slots) that this reader still
  does not decode. QCS qualifies scalar water properties (T/S/C/P/O2/pH/chl/turb/
  CO2), **not current velocity**, so Doppler groups are **skipped** during the
  deployment merge (logged as skipped) and the raw `.bin` stays archived for a
  future dedicated current-profiler feature.

## Verification performed

- Two new self-tests (**37 tests**, was 35): (18) a synthetic mini-session with a
  `<Point>` OUTSIDE `<SensorData>` decodes and its pH is standardized — the layout
  that raised before; (19) two synthetic sibling groups at different rates merge
  onto the finest axis with the slower sensor linearly interpolated (checked at
  the interpolated timestamps).
- Real-data end-to-end: a real 3-group profile (Analog 10 s + CTD 2 s + PAR 5 s)
  read through `read_ctd` → one 1135-row frame carrying pH (med 7.28),
  chlorophyll, turbidity, CDOM, T, C, S, density, soundspeed, O2 and PAR together,
  all in physically sensible ranges.
- Corpus sweep of the staged raw archive (`read_seaguard_deployment` once per
  deployment): **137 of 141 deployments decode and merge**, and **132 now carry
  pH / chlorophyll / turbidity** — variables v6.0 could not read at all. Doppler
  groups are skipped as designed; the 4 that raise are Doppler-only casts (no
  co-located scalar sensor group — nothing for QCS to qualify).
