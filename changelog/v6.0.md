# QCS v6.0 — Read from .bin, batch qualification, dissolved CO2 (imported + QUALIFIED)

> **MAJOR** release (v5.1 → v6.0), developed on branch `improvements-v6.0`.
> MAJOR because the dissolved CO2 imported from the separate logger now goes
> through its OWN quality tests: the flag string gains three positions
> (sensor range, environmental range, spikes) and the output gains a
> `Flag_CO2` column — the qualified layout changes.
> Note: the version bump resets saved QC criteria to the defaults on first
> launch, per the version-gated settings rule.

## Qualify straight from the raw SeaGuard session (Data000.bin)

No more exporting a spreadsheet first: the qualification reads the instrument's
raw binary session directly.

- The AADI **`AADIBXML1.0`** format was reverse-engineered and is decoded by
  `read_seaguard_bin` / `_decode_aadi_bin` in `QCS_DataHandler`: the file is
  self-describing (an embedded XML template holds the sensor/parameter names
  and units; a tag dictionary types every field; data records are sync-framed
  lists of typed values with .NET-ticks timestamps in GMT).
- The decoder emits the exact layout of the instrument's CSV export
  (`Record Time`, `Record Number`, `Pressure[kPa]`, ...), so the whole
  standardization and QC pipeline runs unchanged from there. **Validated
  against a real deployment**: 1550/1550 records; every compared column
  identical to the CSV export within its print precision (~1e-6 relative);
  the .bin actually carries MORE precision (full float32 + milliseconds).
- Multi-file sessions (`Data000.bin`, `Data001.bin`, ...) in the same folder
  are read together, sorted in time.
- Browse accepts `.bin`; the Input type auto-detection recognizes the binary
  magic. The `_QLF` output of a `DataNNN.bin` is named after the SESSION
  FOLDER (e.g. `5650-2104-0-2026-03-16T18-01-00.043Z_QLF`), since `Data000`
  alone is meaningless.
- GMT-3 correction remains an option, exactly as with the CSV export (the
  binary timestamps are GMT).

## Batch qualification (several files in sequence)

- **Seaguard: selecting several files in Browse creates a BATCH** — each file
  (.csv, .xlsx or .bin, mixed allowed) is qualified independently, one after
  another, with the same settings (data type, units, region, criteria) and its
  own automatic `<file>_QLF` output in the chosen output folder. The Output
  name field states the automatic naming and is locked while a batch is
  selected.
- The log shows `=== File i/N: <name> ===` per run and a final
  `Done: batch finished` summary; the completion dialog reports the count.
- **HOBO multi-select keeps its meaning**: several files = redundant
  replicates of ONE deployment (qualified independently, then combined) — as
  before.

## Add CO2 data — dissolved CO2 from the separate logger

The qualified sheet always had a 'CO2 Level (ppm)' column, but the data comes
from ANOTHER instrument. New **"Add CO2 data"** button in the qualification tab
(Seaguard only, Mooring or Profile; single file - not available for a batch):

- Reads the CO2 logger export (`read_co2_file`): comma CSV with the header line
  repeated on logger restarts, date split into Year..Second columns; the value
  imported is the device's 'Corrected disolved CO2 (PPM)'.
- The two instruments sample at different rates (~2 min vs 1 min), so the merge
  (`merge_co2_data`) **linearly interpolates in time** between the two CO2
  samples bracketing each Seaguard timestamp. A timestamp is only filled when
  those samples are at most 2x the CO2 logger's median interval apart (logger
  gaps/off periods are never bridged) and never outside the CO2 coverage.
- The merge happens AFTER the GMT-3 correction: the CO2 logger clock must
  follow the same clock convention as the final qualified sheet (documented in
  the tooltip; a zero-fill triggers a clock-convention warning).
- The button validates the file on selection, shows the loaded name with a "x"
  to remove it, and is cleared/disabled for HOBO and for batches.
- Fixed in the Visualization: the CO2 parameter checkbox said
  'CO2 level (ppm)' while the sheet column is 'CO2 Level (ppm)' (capital L) -
  CO2 data would never be selectable.
- Fixed: the `_QLF` output FOLDER of a `DataNNN.bin` qualification now also
  uses the session-folder name (the inner files already did; the folder itself
  was coming out as `Data000_QLF`).

## Dissolved CO2 is QUALIFIED (result-changing: the MAJOR reason)

The imported CO2 no longer enters the sheet untested — it gets the same QC
treatment as the native variables:

- **Three new tests** in the flag string (data-driven, like all others):
  *dissolved CO2 sensor range* (BAD outside 0–10000 ppm), *dissolved CO2
  environmental range* (SUSPECT outside 100–2000 ppm — broad coastal
  envelope, tune per site in Settings > Parameters) and *dissolved CO2
  spikes* (same robust-sigma factors/window as the other variables).
- New **`Flag_CO2`** roll-up column in the qualified sheet (placed after
  `Flag_chl`); `PARAM_FLAG_COLUMN` maps `CO2 Level (ppm)` → `Flag_CO2`, so the
  Visualization scale defaults use only approved CO2.
- **Remove Bad/Suspect Data** now clears flagged CO2 values — and a latent bug
  was fixed on the way: the dissolved-oxygen removal regex (`o2`) also matched
  `CO2 Level (ppm)`, so O2 flags would have wrongly erased CO2 values (now
  `(?<!c)o2`).
- Settings windows (test switches + Min/Max ranges + spike factors) gained the
  CO2 rows automatically (data-driven); report statistics include CO2.
- **Clock rule made explicit**: the CO2 timestamps are used AS-IS — the GMT-3
  correction is NEVER applied to them (the CO2 logger clock is local; the
  Seaguard side is corrected before the merge, so both meet in local time).

## Defaults

- **Correct GMT-3 is checked by DEFAULT for Seaguard data** (the Brazilian
  timezone is the standard deployment case). It is a per-run choice - a saved
  preference no longer restores it unchecked - and unchecking it survives a
  HOBO round-trip within the session. For HOBO it stays unchecked and disabled,
  as before.
