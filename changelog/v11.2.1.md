# QCS v11.2.1 — Honest first-run message

> **PATCH** release (v11.2 → v11.2.1): one log-message fix, no new features and
> no change to qualification results.

## Fix

- **A virgin install no longer claims settings were reset.** With no settings
  file at all, the startup log said *"saved settings are from a different
  version (None != v11.2); using the current default quality criteria"* — which
  reads as if previous settings had been found and discarded. The first user to
  launch a fresh install concluded exactly that. The no-settings case now says
  what is true: *"Info: no saved settings; using the default quality
  criteria."* The genuine version-change case keeps its message and the
  first-launch dialog (v11.1); the criteria-reset dialog never fired on virgin
  installs (`SETTINGS_RESET_FROM` stayed None) — only the log line lied.

Installers made virgin environments common, which is why a wording flaw that
existed since the version gate (v3.2) only surfaced now.
