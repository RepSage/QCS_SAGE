# QCS v11.4.2 — The installed copy finishes a qualification

> **PATCH** release (v11.4.1 → v11.4.2): two fixes from the owner's first
> end-to-end test of an INSTALLED copy. No change to qualification results.

## The bugs

Both had been invisible for the same reason: every real qualification until
today ran from source, on machines whose settings files were years old. The
installed app runs from a frozen bundle with a fresh settings store — a path
nobody had walked end to end.

1. **The frozen app could not save any plot.** Every figure the program
   writes is an `.svg` (light window documentation, DataView panels, Doppler
   panels), and matplotlib loads its SVG renderer lazily on the first
   `savefig` — so PyInstaller never saw the import and did not bundle it.
   The first real qualification on an installed copy died at the end with
   *"No module named 'matplotlib.backends.backend_svg'"*. The backend is now
   an explicit hidden import in the build recipe.
2. **The Output format box had no factory default** — it filled only from
   saved preferences, which only exist after a successful run. On a fresh
   settings store RUN stopped at *"Select the output format"*. Factory
   default now `.xlsx` (owner's choice).

## Verification

- Suite 52/52; ruff clean.
- The rebuilt bundle verified to contain `matplotlib.backends.backend_svg`,
  and the packaging README now records the lesson: the launch smoke test
  cannot catch lazily-imported modules — check the bundle against the module
  set of a REAL qualification.
