# QCS v5.0 — Unified single-window app + manual-cut dismissal

> **MAJOR** release (v4.0 → v5.0), developed on branch `improvements-v5.0`.
> Headline is the unified single-window app (menu bar + two tabs). It is a MAJOR
> bump because the **manual point cut now changes the qualified output**: cut
> points are flagged DISMISSED (5) and kept, instead of being deleted/NaN'd (see
> "Manual point cut" below). The automated QC tests (thresholds, algorithms) are
> otherwise unchanged from v4.0.

## Unified application (`QCS_App.py`)

The Data Qualification and Data Visualization tools, until now two separate
programs each with its own window and launcher, are merged into a **single
window**:

- **One launcher:** `QCS.bat` opens `QCS_App.py`. The two old shortcuts
  (`QCS - Data Qualification.bat` / `QCS - Data Visualization.bat`) were removed.
- **Two tabs** in a notebook at the top: **Data Qualification** and **Data
  Visualization** — switch between the tools without reopening anything.
- **Menu bar** tailored to the pipeline:
  - **File** — Open Data File (qualification), Open Database File(s)
    (visualization), Set Output Folder, Exit.
  - **Edit** — Qualification Settings…
  - **View** — Dark mode toggle; jump to either tab.
  - **Tools** — Run Qualification; Generate Panels.
  - **Help** — User Manual (opens the HTML), Qualification Help, Visualization
    Help, About.
- **Visualization is now an in-tab wizard:** the old two-window Step 1 → Step 2
  flow became two **stacked frames** in the Visualization tab, swapped by
  **Next** (build the database) and **Back** (choose another database) — no more
  separate windows.

### Under the hood
- `QCS_Main.py` → the qualification UI is now `build_qualification_tab(container,
  root)`; `QCS_DatabaseView.py` → `build_visualization_tab(container, root)`
  (with `build_step1` / `build_step2`). Each module keeps a `__main__` block so
  it can still be run standalone for development. **All qualification pipeline
  logic is unchanged** — only the UI wrapper (root window, header/dark-mode,
  mainloop) moved to the shell.
- **Shared state:** both tabs use one preferences dict (a single
  `qcs_user_settings.json`, no cross-clobbering) and one stdout/stderr redirect
  whose **Execution-log sink follows the active tab**. `install_output_redirect`
  is now idempotent (one shared stream instead of two competing ones).
- Dark mode moved from a per-window switch to the **View menu** (one shared
  setting for the whole app).

## Step 1 of the Visualization tab — new conveniences

- **Instrument auto-detect:** picking database files sets the Instrument
  combobox automatically from the first file's column layout
  (`detect_qualified_layout`); it stays editable, and a failed detection only
  logs a warning.
- **Database preview:** a **Preview** button builds the database immediately
  and shows a summary (rows, sites, period, source files, warning count)
  without leaving Step 1 — the selection can be confirmed before moving on.
  **Next >** reuses the previewed build while the settings are unchanged
  (nothing is read twice).
- **Recent selections:** a *Recent* dropdown keeps the last 8 file selections
  (with their instrument) for one-click refill.
- **'Join Data Files' renamed to 'Build database from a folder'** with a
  clearer tooltip: selecting multiple files already joins them; this mode is
  for sweeping a whole folder tree of QCS outputs.

## One Execution log for the whole app

The Execution log is now a **single panel owned by the shell, fixed at the
bottom of the window** — same position and same message styling (severity
colors) for every pipeline stage: qualification runs, Step 1 preview/build
messages and Step 2 panel generation all write to the same log. (Standalone
dev launches of the tool modules still create their own local log.)

## Round-1 GUI feedback (also in this release)

- Input Type → Data Type → Replicates sit side by side, left-aligned.
- The Help button next to Settings was removed (the Help menu covers it).
- **Tab-switch performance:** the notebook keeps only the native-looking tab
  header; the tabs' content lives in two always-mapped stacked frames switched
  by `tkraise()` — no more full unmap/remap of the whole widget tree per
  switch (slow with sv-ttk).
- Step 2 mouse-wheel scrolling is active only with the cursor over the panel
  (a global binding would leak into the other tab).

## Manual point cut — flag instead of delete (changes results)

The interactive panels for manually cutting spurious points were reworked:

- **Dismiss, don't delete (traceable).** Manually cut points are no longer
  deleted (Depth review) or silently NaN'd (per-variable review). They now get
  **flag 5 (DISMISSED)** and their value is blanked, but the **row/timestamp is
  kept** — consistent with the app's "flag, don't delete" philosophy and fully
  auditable. Setting all of a variable's flag positions to 5 rolls up to
  `Flag_<var> = 5` without corrupting a variable that shares a position (5 is the
  lowest priority in the rollup). **This changes the qualified output** (former
  deleted rows / flag-9 gaps become flag-5 rows), hence part of this release.
- **Better panels.** The cut panels gained on-figure buttons — **Undo, Reset,
  Skip, Done, Help** — a live "N dismissed" counter and an **"X of N" progress**,
  **mouse-wheel zoom** (the toolbar keeps its useful tools but the Zoom lens is
  removed), and a larger window. The panel now opens **in front** of the main
  window (was hidden behind it). Undo/Reset fix the old inability to recover a
  mis-selection; Help pops **over the plot**. (Fixed a bug where the panel opened
  empty and only autoscaled after Reset.)
- **Depth review is automatic; per-variable review is opt-in.** The mooring
  **Depth** review always runs (quick trim of spurious depths from equipment
  handling). **Check Variables** additionally opens a **chooser** (checkboxes +
  **"All variables" / "None"**, taller window) for the per-variable panels; only
  variables with a QC flag column are offered (so the cut is flaggable).
- **Depth cuts carry over.** The Depth whole-row dismissals appear **greyed and
  locked** in the per-variable panels, so the same points are never cut twice.
- The flag legend text for code 5 is now "dismissed (manual cut) / test
  switched off".

## Consistent label casing

All in-app labels, buttons, checkboxes, tabs, menu items, group headers and
window titles were standardized to **sentence case** (only the first word
capitalized), e.g. "Data file", "Input type", "Check variables", "Remove bad
data", "Generate panels" — proper nouns and acronyms (QCS, Seaguard, HOBO,
TSCP, GMT, T-S, PSU, kPa, …) keep their capitals. The manual's interface
tables were updated to match.

## T-S diagram — locked coordinates + clarity

- **Latitude/Longitude are locked when they come from the qualification region**
  (pre-filled via the handoff and read-only, so they can't be mistyped). For a
  standalone qualified file — which stores no coordinates — they stay editable so
  the T-S diagram can still be used.
- The **T-S parameters** dropdown was resized to match the Latitude/Longitude
  boxes exactly (measured against the sv-ttk theme), and its tooltip now explains
  the choice (Conservative T & Absolute S / TEOS-10 vs Potential T & Practical S
  / EOS-80); the "Pratical" typo was fixed. The T-S diagram / lat / long tooltips
  were expanded too.

## Generated panels — navigation and refresh

- **Regenerating replaces the old panels.** `Generate panels` now closes the
  previous figures first, so new panels (e.g. with an edited X-axis window)
  come up fresh instead of opening behind the old ones and looking unchanged.
  (The X-axis window was always applied; the stale windows just hid it.)
- **Panel navigation:** the mouse wheel zooms, **middle-button drag pans**, a
  **Reset view** button (in the toolbar) restores the original plotted limits,
  and the redundant **Zoom lens** was removed from the toolbar.

## Visualization Step 2 — scale, wheel zoom, one action button

- **Scale defaults span the selection.** A parameter's Min/Max default to the
  data's own range over the **selected sites/years** (recomputed when those
  filters change), with **20% breathing room** added on each side so the plot is
  not cramped. User-edited values are kept; auto values follow the selection.
- **Wheel zoom on the generated panels.** Every panel (Seaguard 1/2/3, HOBO
  temperature/light/multi-site, T-S diagram) now zooms in/out with the mouse
  wheel around the cursor.
- **One action button.** "Save view settings" was removed — **Generate panels**
  already saves the current choices before plotting.
- The **T-S parameters** dropdown is narrower, matching the Latitude/Longitude
  boxes (a combobox needs ~2 fewer characters than an entry for the same total
  width, because of its arrow).

## Manual point cut — Cancel/Esc aborts the run

- A **Cancel** button (and the **Esc** key) in the depth/variable cut panels,
  and Cancel/Esc/× in the variable chooser, now **abort the whole qualification**
  and return to the form (nothing is written) instead of proceeding. Skip still
  just skips the current series.

## Visualization Step 2 — smarter, per-sheet defaults

- **Year & Site filters** default to the first available (and, when there is
  only one, it is selected by definition).
- **Select parameters** defaults to the parameters that actually carry data in
  the imported sheet — recomputed on every import, **not persisted**.
- **Scale settings** are per-parameter: a parameter's Min/Max are editable only
  when that parameter is checked (with a panel selected and Fixed scale on),
  pre-filled with the data's own min/max, cleared when unchecked, and **not
  persisted** between sessions.
- **X-axis end** now defaults to the last available date (like the start).
- Panels 1 and 2 dropped the "(mooring)" suffix.

## Visualization Step 2 — smarter defaults

- **Data type is locked to the file.** When a database comes from a
  just-finished qualification, the **Data type** field is set to what the file
  actually is (profile / mooring / HOBO) and **disabled**, so the wrong type
  can't be chosen by mistake. (Opening an arbitrary file still lets you pick.)
- **Non-applicable controls are blank + disabled.** For a mooring the profile
  panel and the Depth-axis min/max are disabled and cleared; for a profile the
  mooring panels and the X-axis window are disabled and cleared.
- **X-axis start defaults to the data.** It is pre-filled with the first
  available date ("Data available"); a saved value is kept only if it falls
  inside the loaded database's range.
- **Coordinates come from the qualification region.** Latitude/Longitude in the
  T-S section are pre-filled from the region chosen at qualification (the
  qualified file does not store coordinates).
- **Clearer panel names.** "Panel 1/2/3" are now "Parameters at a site
  (mooring)", "A parameter across sites (mooring)" and "Vertical profile at a
  site"; the detailed description stays in the tooltip.
- Tightened the spacing around "Data available".

## Smaller fixes from GUI testing

- **One place for the outcome.** The floating "results saved" status line
  between Run and the log was removed; the run start, progress and the
  "results saved to …" outcome all go to the single **Execution log**.
- **Qualify → visualize handoff.** After a qualification run, switching to the
  **Data Visualization** tab pre-selects the just-made file in *Database
  File(s)*, with *Output Path* on its `_QLF` folder and the *Output Name* and
  *Instrument* filled in — ready to preview.
- **Crisper taskbar icon.** The app icon is applied via `iconphoto` with a
  256 px PNG (`qcs_icon.png`) so Windows scales it cleanly on the taskbar
  (Tk's `.ico` `iconbitmap` alone rendered blurry).

## Input default

- The Seaguard **Pressure** unit now defaults to **kPa** (was decibar); it is
  still auto-converted to decibar internally. This is only the pre-selected
  value — the unit is still user-selectable and remembered per machine, so a
  machine that already saved another unit keeps it until changed.

## Panel navigation — smooth zoom/pan, no crashes

- **Gentler wheel zoom** (factor 1.1) and **middle-drag pan matched to the
  toolbar arrows**. On multi-axis panels the shared X transform is applied once
  (not once per stacked axis), fixing the compounding jumps of the first version.
- **Date-axis pan is clamped** to a sane range, fixing a crash ("Date ordinal
  out of range") when panning a time axis very far.
- Toolbar cleanup on every figure: the redundant **Zoom / Home / Subplots**
  buttons are removed (wheel + middle-drag + **Reset view** cover them), and the
  live coordinate readout no longer resizes/jitters the window.
- **Every figure window** now shows the QCS icon and a meaningful title (the
  plot's own title) — including the manual-cut and light-review panels.

## Fixed panel size — labels always fit

- Panel 1 keeps a **fixed window size**; the stacked right axes fit it by
  computed spine spacing and font scaling, and the margins are **measured and
  fitted after drawing**, so no axis label is ever clipped at the edges.
- Y tick labels of the stacked axes are **measured on the renderer** and the y
  fonts shrink until adjacent axes' numbers/titles no longer overlap; crowded
  panels also use fewer, rounder ticks.

## X-axis window and per-type field state

- The X-axis start/end window **actually filters the plotted data** (only the
  chosen hours are plotted and fitted) instead of merely zooming the full series.
- Switching the Data type restores/blanks the fields that apply/don't apply:
  the **X-axis window always resets to the full data range** ("Data available")
  when returning to a time-series type, while the Depth min/max keep the user's
  previous values (or pre-fill from the data's own depth range, like the X axis).
- Non-applicable panel checkboxes auto-uncheck; each Data type pre-selects its
  default panel ("Parameters at a site" for mooring, "Vertical profile at a
  site" for profile) so the selection is never left empty.

## Execution log — one message architecture

- All message prefixes were standardized to **`Info:` / `Warning:` / `Error:` /
  `Critical error:` / `Done:`** (the all-caps `MESSAGE:`/`SUCCESS:` styles are
  gone); severity colors match the prefix case-insensitively.
- Panel generation logs one `Info:` line per plot and a **single green
  `Done: N panel(s) generated in <folder>` summary** (or a `Warning:` when
  nothing was produced) — no more redundant per-panel success spam.
- Empty-semester "no data" messages are no longer printed for semesters with no
  rows at all.

## Step 2 — parameter groups, clearer labels, data source

- **Select parameters is split in two groups:** the main group starts checked on
  every new import (when the data carries it); a **"Rarely used"** group
  (Conductivity, Density, Soundspeed, Pressure) always starts unchecked.
- **Scale settings mirrors the same two groups** with identical row numbering,
  and every row is height-matched with the checkbox column, so each Min/Max
  line sits exactly beside its parameter.
- GUI labels for CO2/O2 drop the word "level" (`CO2 (ppm)`, `O2 (uM)`); the
  data columns keep their original names.
- **Data type** lists `mooring` above `profile` (renamed from "tscp profile");
  Panel 2 was renamed to **"Parameter across sites"**.
- A **"Reading:"** label beside Data settings shows which spreadsheet(s) the
  loaded database was read from.
- The **T-S parameters drop-down list** opens wide enough to read both options
  in full (the closed box stays matched to the Latitude/Longitude width).

## Plot correctness — approved data drives what you see

- **Fixed-scale defaults use only approved data** (flags 1 good / 2 not
  evaluated): the qualified sheet may retain the values of suspect/dismissed
  rows (the operator's choice at qualification), and those extremes no longer
  distort the Min/Max defaults (e.g. a suspect DOM spike of 550 ppb against a
  good range of 0-6 produced a -110..660 default). Mapping via the new
  `PARAM_FLAG_COLUMN` in `QCS_DataHandler`; derived variables without a flag
  column (Density, Soundspeed, CO2, PAR) keep the raw extremes.
- **The y-axis is no longer clamped to the fitted polynomial when the data
  points are visible** — the clamp silently clipped genuine approved data out
  of view (good O2 up to 415 uM was hidden behind a fit range of 164-333). The
  clamp still applies in the tendency-only view (points off).
- **Pressure is never fitted with a tendency line** (tidal signal: a polynomial
  through it is meaningless). Panel 1's first axis and Panel 2 now follow the
  same rule the Panel 1 twin axes already had: the raw series is drawn dashed.
