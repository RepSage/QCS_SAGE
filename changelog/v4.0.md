# QCS v4.0 — Modern interface + qualification overhaul + HOBO support

> **MAJOR** release (v3.2.1 → v4.0), developed on branch `improvements-v4.0`.
> Scope of v4.0: (1) a modernized graphical interface; (2) fixes and QARTOD
> alignment in the qualification — **this part CHANGES results** (see Part 2);
> (3) support for **HOBO** loggers (robust reading + temperature QC + a light
> fouling window — Part 3), with unification of multiple files into one database
> (Part 4) and dedicated HOBO visualization (Part 5); (6) qualification-UI
> refinements; (7) **redundant HOBO replicates** (2–4 loggers combined); (8)
> light-QC refinements that supersede parts of Part 3 (fouled light is BAD, and
> the cutoff is the final sustained decline); (9) all generated spreadsheets are
> `.xlsx`, a no-terminal launch, and interface polish; and (10) full migration
> of the project to English.
> Note: because the preferences are version-controlled, the quality criteria
> saved from v3.2.1 are replaced by the current defaults on the first run
> (intentional; file paths and last file choices are preserved).

## Part 2 — Corrections and improvements to data qualification

### Bug fixes
- **Cross-variable contamination in rate-of-change**: the test marked a row as
  "not evaluable" if ANY previous test — from any variable — had flag 4/9
  on that row (e.g. a salinity spike changed the temperature RoC). Now
  propagation uses only the flag positions of the variable itself (`var_positions`),
  plus a direct NaN check on the previous value.
- **A window smaller than the sampling interval became a silent no-op**: with the
  default 30M window and data sampled every ≥30 min, the rolling σ was all NaN and the
  spike/RoC tests **never failed anything, without warning** (verified: a 15 °C jump
  passed unharmed). Now windows with fewer than 11 samples fall back to the σ of the whole series,
  with a warning in the log.
- **Endpoints and gap neighbors in the spike test** received flag 1 (good) without having
  been evaluated; now they receive 2 (not evaluated).
- **Flat line "escaped" with a sporadic NaN**: any NaN in the window blocked
  detection — a stuck sensor emitting occasional NaNs was never caught. The count
  now skips NaNs (and the test was vectorized: O(n) instead of O(n·k)).
- **Vertical gradient did not use depth**: it was a rate-of-change on the profile's
  temporal sequence. Rewritten as a real |ΔV/Δz|, with deviation measured relative to the
  typical gradient (median) of the profile; pairs with |Δz| < 0.05 m are not evaluable.
- **Series plot broke when crossing the year** (the X-axis end limit used the year of the
  first timestamp); the title now shows the full period.
- **Panel 3 was saved with the name `panel1_...`**; corrected to `panel3_...`.
- **"Check Variables" and depth trimming** used `plt.show(block=True)` inside
  the RUN callback — the same freezing pattern fixed in v3.2.1; they now wait
  in the Tk loop.
- **DatabaseView multi-file**: selecting several .xlsx (promised in the tooltip)
  broke loading; the files are now concatenated. Databases without a
  `Datetime`/`Site` column get a clear message instead of a raw exception.

### QARTOD alignment (CHANGES results)
- **Environmental range → SUSPECT (3)** instead of BAD (4): a value outside the regional
  envelope is suspect (a real extreme event is possible); only the sensor range remains BAD.
  With "Remove Bad Data", values outside the environmental envelope **are no longer removed**
  automatically (use "Remove Suspect Data" for the old behavior).
- **Rate-of-change → SUSPECT at most** (QARTOD): a real rapid change exists.
- **Robust σ (1.4826×MAD)** as the reference for the spike and RoC tests: the
  outlier itself no longer inflates the threshold (it masked smaller spikes). Where the
  MAD degenerates, it falls back to the standard deviation.
- **Density inversion tolerance** (0.03 kg/m³) now configurable in Settings;
  **longitude** became a field in the main window (it was hardcoded to -40).

### Traceability
- **Columns `Flag_T`, `Flag_S`, ... `Flag_tur`** in the qualified file: the variable's
  worst flag in each row (4>3>9>1>2>5) — no longer necessary to decode the string.
- **`QCS_flag_legend.csv`**: position→test→variable of the flag string + meaning
  of the codes (previously only existed in the source code).
- **`QCS_test_report.csv`**: counts per test (good/suspect/bad/missing/etc.),
  previously printed only to the console.
- **`QCS_report.csv` extended**: bad/suspect/missing counts of the 9 variables
  (previously only T/S/C/P), timestamp checks (backward steps, duplicates, gaps >3× the
  median interval) and `Valid` discounting rows bad for any variable.
- **Statistics table** with all present variables (previously only T/S/P).
- **`clean_below_zero` reports counts** of values clamped/discarded per
  variable in the log (previously it discarded silently).

### Usability
- **"Execution log" panel in the main window**: progress per test, warnings and
  the destination of the results (previously only in the console).
- **Generate Panels saves the settings implicitly** (end of the trap of the
  save→generate flow in two clicks).
- **Validations**: latitude [-90, 90] and longitude [-180, 180] with a message (previously
  an invalid latitude silently became 17.5); Site Code limited to 5 characters;
  invalid values in Settings are now listed in a warning (previously ignored
  silently) and the time-window format is validated (`2D/3H/30M/45S/WHOLE`).
- **"Reset to Defaults" button** in the Settings window.
- **Config File (.json) is applied when selected** — the Settings window now
  reflects the file (previously it was only read at RUN time).

### Verification performed (Part 2)
- `QCS_SelfTest.py` expanded from 14 to **20 cases**, including regressions for each
  fixed bug (cross-variable contamination, undersized window, endpoints,
  flat line with NaNs, gradient by Δz, environmental severity, Flag_ columns).
- **End-to-end test through the GUI** with synthetic Seaguard data (seed 123) containing
  planted defects: a T spike, an S flat line (41 values), a value outside the
  environmental envelope and C NaNs — all detected with the expected flags, without mass
  false positives, and the four report files generated correctly.

## Part 3 — Support for HOBO instruments (Pendant Temp/Light)

### Robust reading (`read_hobo`, replaces `read_unified_hobo`)
- Accepts the HOBOware **.xlsx and .csv** exports, dynamically detecting the
  header row (tolerates the title line above it) and the csv delimiter.
- **Headers in Portuguese or English** and **broken accentuation** (reads csv testing
  utf-8/cp1252/latin-1).
- **Automatic light unit** from the channel label: `Lux` or `lum/ft2` (converted
  to lux, ×10.7639).
- **Variable sampling frequency** across files: uses the real median interval.
- **Deployment window from the logger events** (`Coupler Detached/Attached`,
  `Stopped`, `End Of File`): discards rows outside the in-water period and the
  event-only rows (no measurement).
- **Trimming of out-of-water readings at the ends** by temperature jump
  (`hobo_edge_temp_tol`, default 1.5 °C), with a safeguard against removing >10% of the series.
- Each step is logged; **every error self-locates** in the format
  `HOBO reader (file): what was missing` (e.g. missing time/light column).

### Temperature QC (HOBO)
- Reuses the applicable mooring set: sensor + environmental range, 3-point spike,
  rate-of-change and flat line. Outputs the `Flag_T` column.

### Light usage window (fouling test — new)
- `light_fouling_baseline`: the **clean-water baseline** is the largest daily peak of the
  first `lux_baseline_days` days; light becomes **SUSPECT** (value kept) when the
  daily peak stays below `lux_cutoff_frac` × baseline for `lux_sustain_days`
  consecutive days. **It does not assume monotonic decay**: it measures the fraction of days that still
  reach the threshold after the cutoff and, if it exceeds ~20%, emits a **WARNING** that the drop
  is not permanent (possible cleaning/redeployment, partial fouling or cloudy weather —
  the file may contain more than one deployment).
- **Visible and traceable parameters** (user's request): they live in Settings
  (Parameters tab, prefix `lux_*`), appear written **on the light window plot** itself,
  in the **log** and in `QCS_test_report.csv`.
- **Interactive review before applying**: shows the daily light envelope with the proposed
  cutoff; a click moves the date, the **N** key removes the cutoff, Enter/close confirms
  (no `plt.show(block=True)` — it waits in the Tk loop). The final plot is saved as
  `QCS_light_window.svg` in the output folder.
- Light is qualified with the `Flag_lux` column; zero at night is a **valid** value
  (never becomes NaN); negatives become 0.

### Debug and messages (user's request)
- **Errors with exact location**: the error dialog points to `file.py, line N, in
  function()` (deepest QCS frame) and the **full traceback** goes to the log.
- **5-stage pipeline** announced in the log (reading → preprocessing → tests →
  output/reports → plots), to quickly locate where a run failed.

### Collateral fixes
- Plots stop generating empty SVGs: fully-NaN variables (the TSCP columns created
  for a HOBO file) and the `Flag_*` columns **are no longer plotted** (previously the
  Seaguard DataView generated 9 meaningless `Flag_...` plots).
- `clean_below_zero` treats light/luminosity as PAR (zero is valid).

### Verification performed (Part 3)
- `QCS_SelfTest.py` expanded to **25 cases** (new: fouling with permanent decay
  → firm cutoff; with recovery → warning; light-window flags and short
  series; night light preserved; `Flag_lux` + removal of suspect light without affecting
  temperature). All pass.
- **End-to-end test through the GUI with the real PAB3 file** (2024-09-13–2025-03-24,
  2309 rows): correct reading (deployment window applied, 1 out-of-water reading
  trimmed, unit detected), temperature QC (1 flat line detected) and light window
  reviewed and applied, with `Flag_T`/`Flag_lux`, the reports and the
  `QCS_light_window.svg` generated. The PAB3 analysis revealed that the light **does not decay
  monotonically** (sporadic clear peaks return to baseline) — the proposed
  test marks the cutoff early and the operator adjusts it in review; documented as a case
  where human judgment is necessary.

### HOBO's own output format
- **HOBO output standard** (`order_var(..., data_type='hobo')`): the qualified spreadsheet
  contains **only the measured variables** — `Temperature (degC)` (always in Celsius) and
  `Luminosity (lux)` — with the **same metadata block** as the Seaguard standard
  (`Sample number`, `Datetime`, `Expedition`, `Site`, `Longitude`, `Latitude`,
  `Battery voltage (V)`, `Flag`, `Flag_T`, `Flag_lux`, `QCS version`). The other
  TSCP variables do not appear (Seaguard and HOBO are never "stackable" spreadsheets).
- **Light unit standardized to lux** in the output, whatever the input unit
  (lux or lum/ft²): lux is the SI unit of illuminance (lm/m²); HOBOware's "lum/ft²"
  is the US unit (foot-candle) and is converted on reading.
- `Site`, `Latitude` and `Longitude` are filled from the interface fields,
  in both HOBO and Seaguard (previously latitude/longitude came out empty in Seaguard).
- For HOBO, **only the temperature tests** run (those for S/C/P/etc. do not apply),
  so the report and the `Flag_` columns no longer carry meaningless positions.
- The data subfolder becomes `QCS qualified hobo data` (Seaguard remains
  `QCS qualified tscp data`).

### Known limitations (Part 3)
- Supports **one light cutoff per file** — which is exactly the user's flow (each
  sensor cleaning generates a new file). PAB3 itself shows light recovery in the
  middle of the file, which is why it is flagged as a warning to investigate.

## Part 4 — Spreadsheet unification (single engine) + optional Lat/Long

### Lat/Long out of the qualified spreadsheets
- Coordinates are **never** written to the qualified file (user's decision):
  it guarantees that **every spreadsheet has exactly the same column layout**, whatever
  the instrument or data type — it avoids column-position errors when reading
  files generated at different times. `order_var` discards Latitude/Longitude
  if they appear.
- Lat/Long remain in the interface fields, used **only to RUN** the
  qualification (pressure→depth and density inversion test); they are now
  **optional** (an invalid/empty value falls back to the default with a warning in the log, without freezing).
- The **only** coordinate requirement is the **T-S Diagram** (in the DatabaseView),
  where lat/long enter the gsw absolute salinity / conservative temperature and do not
  cancel out: without valid lat/long the diagram is skipped with a clear warning.

### `build_database` — single unification engine (replaces `join_files_to_database`)
Revision requested by the user; the old mechanism had real defects:
- **`header=1` in the CSVs** — the first data row became the header (it corrupted
  any unification from csv); now `header=0`.
- **It ingested the report files** (`QCS_report.csv`, `QCS_tscp_stat.csv`, and the
  new v4.0 ones) as if they were data; now anything starting with `QCS_` is ignored.
- Rigid folder structure with silent failure; no provenance; no schema
  validation; `os.chdir` as a side effect.

The new engine (user's decisions on 2026-07-04):
- **Two inputs**: parent folder (recursively scans the subfolders
  `QCS qualified tscp data` / `QCS qualified hobo data`) or manual file
  selection (multi-selection). Reads .csv and .xlsx (format selector removed from the GUI).
- **Instrument selector** (Seaguard/HOBO) in the DatabaseView Step 1 window; the
  layout of each file is detected by its columns and **mixing types is refused**
  with a clear message (spreadsheets are never "stackable").
- **Exact duplicates** (site+timestamp+values) are discarded keeping the
  first, with a warning; overlaps with **different** values are kept and
  reported with the list of files involved.
- **`Source file`** column (provenance of each row); sorting by Site+Datetime;
  per-site summary (rows and period) shown in the visualization window log.
- Self-located errors (`build_database: ...`).
- HOBO database in the visualization: the parameter list becomes Temperature+Luminosity,
  with a dedicated color for light in the panels; `Flag_T`/`Flag_lux` travel in the database.

### Verification performed (Part 4)
- `QCS_SelfTest.py` expanded to **28 cases** (new: optional Lat/Long not created
  empty; discovery in a synthetic tree with a decoy report, dedup, provenance,
  mixing refusal and correct reading of a qualified csv).
- **E2E**: HOBO database assembled from the real PAB3 output (reports ignored, correct
  summary) and the full DatabaseView GUI flow (Step 1 with selector → database →
  Step 2) with screenshots.

### Known limitations (Part 4)
- The dedicated HOBO visualization (light-specific panels with shading of the
  suspect window) is left for the next phase — today the HOBO database uses the
  existing mooring panels 1/2. **(Resolved in Part 5, below.)**

User requests after a visual review of the qualification tool.

- When choosing the **Data File**, the **Output Folder** now automatically replicates
  the file's folder and the **Output File Name** comes filled with the file's base name

### Interface simplification
- **"Config File" field (import .json) and "Export Settings" button removed**: the

  duplicated the function and were confusing. The `apply_config_file` / `export_config`

### Irrelevant fields disabled for HOBO
- With **Input Type = HOBO**, the following are disabled: **Data Type**, **Units** (pressure and
  conductivity), **Correct GMT-3**, **Select Profile Data** and the region fields —
  none of this applies to a temperature and light logger. Data Type is treated
  internally as non-profile.
- **Data Type and the Units are emptied** (blank) in HOBO so as not to lead the
  user into error, but **they store the last Seaguard selection and restore it** when
  switching Input Type → Seaguard back in the same session.

### Coordinates by region (instead of typing lat/long)
- The numeric **Latitude/Longitude** fields became two cascading dropdowns:
  **Macroregion** → **Region**. For now the only macroregion is **Brazil**, with the
  sectors (in English) Amazonian Reefs/North, Northeast–northern, Northeast–eastern,
  East/Abrolhos, Southeast, South; each region carries a representative
  latitude/longitude. The macroregion was created already anticipating the inclusion of other parts of
  the world in the future. More intuitive and proof against typing errors; the chosen region
  (and the coordinates used) is recorded in the log for Seaguard.
- **Scientific note (changes the result negligibly):** the coordinates are
  used only to RUN the qualification — pressure→depth conversion (depends on
  sin²(lat), so the sign does not matter) and the density inversion test (uses
  lat/long in gsw). The effective latitude default is no longer `+17.5` (Northern
  Hemisphere — inconsistent for Brazil) and became the **negative** latitude of the chosen
  region (default: East/Abrolhos, -17.5). The effect on depth is nil (symmetric formula)
  and on the density inversion it is negligible (a systematic shift of absolute
  salinity that practically cancels out within the profile). Since v4.0 is already
  MAJOR and revises criteria, this is absorbed within the version itself.

### Visual adjustments to the Settings window
- **Dashed focus ring** on the selected tab's label removed (keyboard focus
  passes to the tab content; independent of the sv-ttk/clam theme).
- **Scrolling** of the tabs (incl. "Factors per Variable") only kicks in when the content
  exceeds the visible area — no more "empty space" created when scrolling content that
  already fit.
- **Slowness when switching tabs:** I tried to "warm up" the tabs on opening to
  anticipate rendering, but it **did not solve** it in the user's test (ttk renders
  each tab's heavy content on first display). The attempt was **reverted**
  so as not to burden opening with no gain. A real fix would require building each tab's
  content on demand (a larger refactor) — left for the future if it becomes a nuisance.
- **Density Inversion** grouped with the vertical gradient tests, in the group
  "Vertical Gradient & Density Inversion Tests (profiles)" (both are profile tests).

### Confirmation (no change)
- Leaving **all tests ON** with a device that does not have those variables
  (e.g. HOBO) **does not cause a problem**: a missing variable simply receives the
  "not evaluated" flag (2), with no error or incorrect data (and for HOBO the sequence is already
  filtered to only the temperature tests). Behavior maintained.

## Part 7 — HOBO redundant replicates (2–4 loggers)

Users often deploy 2 (up to 4) HOBO loggers at the same spot for redundancy,
producing 2–4 spreadsheets per deployment. v4.0 qualifies them together and
combines them into a single, more reliable series.

### Combination engine (`combine_hobo_replicates`, `QCS_DataHandler.py`)
- Each replicate is qualified **independently** first (its own fouling-window
  review and flags) — raw data is never averaged or discarded at qualification.
- **Temperature:** the **mean** of the replicates that are acceptable
  (`Flag_T <= 2`) at each timestamp. Replicates are aligned to the first
  replicate's timestamps by **nearest match within half the sampling interval**
  (the loggers rarely share the exact same clock) — no resampling/interpolation.
  The between-replicate **spread** (max − min) is kept in a new
  `Temperature spread (degC)` column; when it exceeds 0.5 °C the combined
  `Flag_T` is set to **SUSPECT (3)** — the replicates disagree, a QC/agreement
  signal rather than a silent average.
- **Light:** the per-timestamp **MAX** of the non-fouled readings
  (`Flag_lux != 4`) — the brightest sensor is the least fouled, hence closest to
  the truth. The combined usable window is **extended to the last replicate to
  foul**: light stays good while at least one replicate is clean, and becomes
  BAD (4) only once every replicate is fouled. Naive averaging of light and
  discarding the "worse" replicate were explicitly rejected.

### UI + run flow (`QCS_Main.py`)
- A **Replicates** combobox (1–4, HOBO only) next to Input Type. With N > 1,
  **Browse** multi-selects exactly N files in one run; the count is validated.
- `start_qualification` loops the full pipeline **per file** (each replicate
  keeps its own interactive light-window review), then combines the N qualified
  series and writes a combined product to a
  `<site>_<start ddmmyy>_<end ddmmyy>_combined_QLF` folder (or the Output File
  Name if the user set one).
- The combined folder also receives a **`QCS_combine_method.txt`** documenting
  the temperature/light combination rules (same traceability treatment as the
  fouling threshold), and a copy of each replicate's light-window plot renamed
  `QCS_light_window_<replicate>.svg`.
- The **Output File Name** field follows the replicate count automatically:
  `<file>_QLF` for N = 1, and the combined name for N > 1 (re-derived when the

## Part 8 — HOBO light QC refinements (supersedes parts of Part 3)

Refinements to the light fouling test after review on real deployments. These
**change results** relative to the Part 3 description.

- **Fouled light is now BAD (4), not SUSPECT (3).** Light after the fouling
  cutoff is genuinely unusable (the sensor is covered), so it is flagged
  `Flag_lux = 4`. This lets the user's natural **"Remove Bad Data"** toggle drop
  the fouled light while the good **temperature** (`Flag_T`) is never touched
  (removal is per-variable in `handle_output_file`). Nothing is auto-deleted —
  values stay in the sheet until the user removes them. DataView shading and
  cutoff detection now key on `Flag_lux == 4`. (Old qualified files must be
  re-qualified to get the new code.)
- **Cutoff = the final sustained decline that never recovers**, not the first
  dip. The proposed cutoff is the start of the **last** run of ≥ `sustain_days`
  below the threshold that does not recover to it; light that later climbs back
  above the threshold is **kept**. Rationale: fouling only attenuates light, so
  a recovery means the sensor is not permanently fouled — the old first-dip rule
  over-flagged recovered data. Trade-off (accepted): less conservative, so the
  interactive review remains the safeguard.
- **"Clean-water baseline" renamed "Clean-sensor baseline"** — the baseline
  reflects the unfouled sensor, not water clarity. Definition unchanged
  (max daily peak of the first `lux_baseline_days` days; threshold =
  `lux_cutoff_frac` × baseline).
- **Interactive review improvements:** the review window gained **Suggested
  cutoff**, **Remove** and **Help** buttons and keyboard shortcuts (**S** =
  suggested, **R** = remove); the "no cutoff" message moved to the top; the
  cutoff label shows **date + time**; and the plot title now shows the **file
  name** (`site (file_name)`) so the reviewer knows which replicate they are on.
- **Fixed-scale luminosity range** added (`env_min_lux` / `env_max_lux`) for the
  fixed-scale light plots.

## Part 9 — Output format, launch and interface polish

### Every generated spreadsheet is now .xlsx
