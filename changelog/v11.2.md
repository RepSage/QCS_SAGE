# QCS v11.2 — Self-update from GitHub and Program Files support

> **MINOR** release (v11.1 → v11.2). No QC result changes — nothing in the
> qualification path was touched; the additions live in the app shell, the
> theme helper and the packaging recipe.

## 1. Update check with one-click install (`QCS_Update.py`)

On startup the app asks GitHub's releases API — in a background thread, with a
short timeout — whether a newer release exists. Offline (a field notebook's
normal state) the check stays silent. When a newer version is found, a dialog
offers to **download and install it in one click**: the setup asset is
downloaded with a progress bar, the app closes, the installer upgrades in
place (same AppId) and reopens the updated app. *Help → Check for updates…*
runs the same check by hand, with explicit "up to date" / "unreachable"
answers.

Design boundaries, on purpose:

- **The headless and batch paths never touch the network.** The checker lives
  behind `QCS_App`, which the batch drivers and the harness never import.
- **Every network failure is silent on startup** (and explicit on the manual
  check). An update notice must never block or crash qualification work.
- A release without a `QCS_Setup_*.exe` asset falls back to opening the
  releases page in the browser.
- A malformed remote tag is ignored; a downgrade is never offered
  (self-tested: upgrade / same / downgrade / junk tag).
- **Requires the repository to be public** — the API answers anonymously. While
  it is private the check simply finds nothing, harmlessly.

## 2. Program Files installs work (`writable_app_dir`)

The app writes its settings and crash log beside the exe — correct for
per-user installs and the portable unzip, impossible under `Program Files`,
which is read-only for regular users. `QCS_Theme.writable_app_dir()` now
probes the install folder with a **real write** (`os.access` lies on Windows)
and falls back to `%APPDATA%\QCS`. Both tabs' `settings_store_path` and the
crash handler route through it. Running from source, the path is byte-identical
to every earlier version (self-tested).

## 3. Dual-mode installer (packaging, no version impact of its own)

One `QCS_Setup_v11.2.exe` now asks: **all users** (Program Files, admin) or
**just me** (user area, no admin — the field-notebook mode). Also:
`CloseApplications` so the self-update can upgrade a running install, and a
silent upgrade relaunches the app when done.

## Verification

50 self-tests pass (2 new), ruff clean. Source app opens under the new wiring
(window titled v11.2, no crash log). The full self-update loop — install
v11.1, see the v11.2 offer, one click, reopen updated — is exercised after the
release exists with its setup asset attached; the recipe for that test is in
STATUS.md.
