# v14.1.0 - pool sites, stale .hobo warning and two field issues

Pool data return as ordinary sites, raw `.hobo` files warn about stale memory,
and the fixes for GitHub issues #49 and #50; QC rules unchanged
(MINOR: v14.0.3 -> v14.1.0).

## Fixed

- **A Doppler spreadsheet export is refused with the reason (#49).** A
  spreadsheet exported from the current profiler (DCPS) was read as a scalar
  PROFILE, and refused as Doppler without saying why. The export is now
  recognised from its DCPS header. It is refused for every input type, and the
  log says so as soon as the file is chosen: current data are read only from
  the native session, `Data000.bin` with its `Config.xml` beside it. An export
  carries neither the cell geometry nor the configuration the current QC
  needs.
- **One QCS window per user, with a splash at once (#49).** On a clean
  install the first start showed nothing for a long time: the shell loads its
  heavy modules before any window can exist, 3.5 s even warm. So the operator
  started QCS again and got two windows. A small splash now appears before
  that loading. A second start brings the running window to the front and
  exits, and the main window is raised when it appears.
- **The installer's 'open the user manual' checkbox is translated (#49).**
  A Portuguese install showed the launch checkbox in Portuguese and this one
  in English. The manual itself stays in English.

## New

- **Depth (m) as an opt-in Mooring panel parameter (#50).** Depth joins
  Pressure in the 'Rarely used' parameter group of the Visualization tab, with
  its own colour. Like Pressure it is tidal, so it is drawn as a dashed raw
  line and never fitted. It is greyed out for a profile, whose vertical axis
  it is.
- **Raw .hobo files warn when their decode may be stale memory.** A 64 KB
  `.hobo` is a dump of the logger's whole memory, a launch does not clear it,
  and the header has no sample count. When the deployment's end marker is
  lost, the decoder runs on into an older deployment's samples. When the
  decode runs past the moment the file was saved, the log now says so and
  explains the two possible causes. Nothing is cut: in 12 of 157
  export-verified archive pairs the genuine data end after the save time,
  through a wrong PC clock, while every proven stale tail overruns by 9 days
  or more.
- **Pool data are ordinary sites.** The Curated Database catalogues
  `PISCINA_SGOM` and `PISCINA_PLES` beside the monitoring sites. Only the old
  special-collection folders (`_PISCINAS`, `_EXPERIMENTOS`, `_SEM_SITIO`)
  stay out.

## Note

The replicate-decision ledger shipped with the program gains the RRDM 23a and
pool rows. The archive operations of this round are recorded in
`sourceCode/batch/CORPUS_LOG.md`, not here:
- RRDM 23a qualified from native `.hobo` with stale-memory guards;
- PLES 2025S2 requalified with a third logger;
- the pool data staged and qualified as sites.

The index went from 281 to 303 products. Official qualification, thresholds
and timebase rules are unchanged. As on every version change, the first
launch applies the current QC defaults and says so.

## Verification

- **Self-test suite: 93/93; Ruff clean.** New cases cover the save-time
  warning (no sample removed), DCPS export recognition, the Depth panels and
  their profile gate, and pool sites in the catalog.
- **The real corpus re-swept unchanged.** All 188 Database `.hobo` decodes
  are identical to the previous reader. The RRDM 23a replay is byte-identical
  to the published products (9 of 9 tables).
- **Single instance verified offscreen, 5 of 5.** The checks:
  - a second start is refused and reaches the first;
  - an activation is queued until the window exists;
  - a start after a clean exit owns the lock;
  - a crashed instance's lock is recovered.

  The real shell booted through the new startup with the splash closed and
  operator preferences untouched. A launch from the installer on the
  operator's desktop was not tested.

## Install

Download and run `QCS_Setup_v14.1.0.exe` from the GitHub release. Installing
over an existing copy upgrades it in place and keeps saved folders and
interface preferences; the version gate applies the current QC defaults on the
first launch.
