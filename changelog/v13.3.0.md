# QCS v13.3.0 - direct feedback without a GitHub account

> **MINOR** release (v13.2.4 -> v13.3.0). Quality-control tests, thresholds,
> flag layouts, database rules and qualified values are unchanged. This release
> replaces the external GitHub issue page with an in-app submission form.

## Fixed

- **Reporting a problem no longer requires a GitHub account.** Bugs &
  Suggestions stays inside QCS while the operator writes and submits the
  report, instead of opening GitHub's sign-in-dependent issue form.

## New

- **The internal form collects a title, description and optional name.** Title
  and description are validated, and the running QCS version is included
  automatically.
- **Submit report creates the GitHub Issue directly.** QCS sends the form to a
  small Cloudflare Worker in a background thread, keeps the interface
  responsive, and confirms the resulting Issue number without opening a
  browser or requiring the operator to send an email.
- **The three fields use the full dialog width.** Each label sits above its
  field, the optional name is identified by its in-field hint, and ordinary
  Ctrl+C remains available if text must be copied before closing the form.

## Security and privacy

- **The GitHub credential is never included in QCS.** It is stored only as an
  encrypted Cloudflare Worker secret and is limited to Issues in the
  `RepSage/QCS_SAGE` repository.
- **The public endpoint validates and limits submissions.** It accepts only
  small JSON reports, revalidates every field, uses a honeypot, limits each
  source IP to three attempts per minute and never returns upstream error
  details or credentials.
- **Submitted reports are public.** The form warns operators not to include
  passwords, private data or other sensitive information.

## Note

- **QC and database semantics are unchanged.** No reader, test, threshold,
  flag, qualification pipeline, curated-corpus rule or visualization rule
  changed in this release.

## Verification

- **The QCS self-test suite passed 72/72.** The feedback checks cover required
  fields, exact UTF-8 JSON, TLS verification, the expected Issue response,
  rate-limit errors and a missing-service fallback without contacting the live
  endpoint.
- **The Worker tests passed 9/9.** They cover validation, field limits, the
  honeypot, public Issue formatting, the health route, one exact GitHub call,
  rate limiting, sanitized upstream failures and request-size/content-type
  refusal. Wrangler 4.127.1 also completed its deploy dry run and recognized the
  three-requests-per-minute rate-limit binding.
- **The production Worker passed its initial live checks.** Its health route
  returned HTTP 200 and a validation-only submission returned the expected
  HTTP 400 without creating an Issue. The exact released client path then
  created public Issue #41 through the Worker, and the public page returned
  HTTP 200 with its expected title.
- **Both graphical implementations passed focused probes.** The released Qt
  shell and retained Tk fallback showed Bugs & Suggestions immediately after
  Help, exposed three full-width stacked fields and only the Cancel and Submit
  report buttons, disabled editing during a mocked background submission,
  confirmed the returned Issue number and closed cleanly. The probes no-op'd
  both preference writers and made no additional network submission.
- **The final frozen candidate passed its launch smoke.** PyInstaller 6.22.2
  produced a 301,453,201-byte onedir bundle containing 2,334 files, including
  the feedback module and CA bundle. The executable stayed alive and responsive
  for the 12-second launch smoke with no bundled preferences or crash log. Inno
  Setup 6.7.3 produced `QCS_Setup_v13.3.0.exe` (81,760,981 bytes; SHA-256
  `D0A55587433E7BF18C767123943DB1795712079C06B606F0EC51933AB6AFCB9F`).

## Install

After publication, download and run **QCS_Setup_v13.3.0.exe**. Installing over
an existing copy upgrades it in place and keeps saved folders and interface
preferences.
