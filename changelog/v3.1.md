# QCS v3.1 — Cleanup, handling of non-positive values and per-variable factors

> **MINOR** release (v3.0 → v3.1): compatible features and adjustments. The "≤ 0"
> handling on the optical variables slightly changes what data is retained (it keeps
> values that were previously discarded), documented below.

## 1. Code cleanup (no behaviour change)
- Removed functions with no caller anywhere: `search_values`, `search_times`,
  `read_unified_excel` (DataHandler); `depth_range_test`, `z_score_method`,
  `z_score_spike_test` (Tests); `plot_database_panel2_DEPRECATED` (DataView).
- Also removed: the commented-out block of the old `range_test`, an orphan import and
  unused local variables. ~270 fewer lines of dead code.
- Kept (with a protective comment) the `selector` variables, which hold the live
  reference to the `RectangleSelector` — removing them would break interactive
  selection.

## 2. Handling of "≤ 0" on the optical variables
- Chlorophyll, turbidity and CDOM (organic matter) are physically ≥ 0. Now:
  - a small negative (noise around zero) → **rounded to 0** (kept as "~0");
  - a gross negative (sensor error) → **NaN**.
  - The boundary between the two: **5% of the variable's environmental range**
    (adjustable through env_min/env_max).
- **PAR**: irradiance is physically ≥ 0; small negatives at night are the sensor's "dark"
  noise → **clamped to 0** (kept) rather than discarded as NaN. This fixes night-time PAR
  readings disappearing (blank cells).
- Every other variable keeps `≤ 0 → NaN`.
- Implemented in `QCS_DataHandler.clean_below_zero` (replacing the loose block in
  QCS_Main).

## 3. Flag-system refactor (no behaviour change)
- `handle_output_file` no longer uses **hardcoded positions**: it now receives
  `flag_layout` (each test's variable, in sequence order) and maps position→variable
  through `FLAG_BUCKET_MAP`. Removed ~90 lines of `if flags[i][N]...` and the
  `drop_overlap`.
- Equivalence demonstrated: classification **identical** to the previous one over real
  data (new logic vs. a replica of the old logic).
- The gain: adding new tests no longer risks misaligning the flags.

## 4. Sensor range for the secondary variables (O₂, pH, chlorophyll, turbidity)
- New sensor-range tests (the instrument's limit) for these variables, which previously
  had only an environmental range. Default ranges: O₂ 0–500 µM, pH 0–14, chlorophyll
  0–500 µg/L, turbidity 0–1500 FTU. The mooring flag string went from 30 → 34 characters.

## 5. Per-variable factors and window
- `fail_factor`, `susp_factor` and `time_window` are no longer global and are now
  **per variable** (T, S, C, P, pH, chlorophyll, O₂, organic matter, turbidity), used by
  the spike, rate-of-change and vertical-gradient tests.
- A new **"Factors per Variable"** tab in the Settings window, laid out as a **table**
  (one row per variable; Fail / Susp / Time window columns).
- Stored in `CONFIG['tsFactors']`, persisted in the preferences and included in the
  configuration export/import (JSON). The defaults are preserved (3 / 2.5 / 30M for all),
  so results do not change for anyone who adjusts nothing.

## Decisions
- Biofouling / attenuated signal: **out of scope** (the equipment never spends more than
  24 h in the water).
- Flat line: kept counting by number of samples.
