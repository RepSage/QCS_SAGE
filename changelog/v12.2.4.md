# QCS v12.2.4 - the Doppler run says where it is, and its database opens

> **PATCH** release (v12.2.3 -> v12.2.4). The QC rules and the default criteria
> are UNCHANGED: no flag, threshold or test logic was touched. What changes is
> a progress readout, a validation gate and a warning's key - all found by the
> owner's first end-to-end test of a DCPS session.

## Data qualification

- **The progress bar follows a Doppler run.** It reads the pipeline's own
  `Stage k/N` markers from the log, but the number of stages was hardcoded as
  `/5`: the scalar pipeline logs five stages and the current-profiler one logs
  four, so a DCPS run matched nothing and left the bar indeterminate and
  blank from start to finish. The marker's own denominator is now used, in the
  single-file and in the batch/replicate readouts alike ("File 2/3 - Stage
  3/4"), which also means a future pipeline with another stage count needs no
  change here.

- **A DCPS session no longer offers a collection type to choose.** The Data
  type was already set to *TSCP Doppler* when the selected `.bin` turned out to
  be a current profiler, but the field stayed selectable, so *Profile* or
  *Mooring* could still be picked over a file that is neither. It is now shown
  and locked - the file decides it - and picking a scalar Seaguard session
  gives the Profile/Mooring choice straight back. Both shells behave the same.

## Data visualization

- **A qualified Doppler database can leave Step 1.** Every other piece of the
  tab already handled the current profiler - the instrument is auto-detected
  from the file's columns, the Data type reads *Seaguard TSCP Doppler*, and
  Step 2 renders the four current panels - but the Step 1 validation accepted
  only *Seaguard* and *HOBO*, so **Next >** answered "Select the instrument
  that produced the files" and refused to move. The gate now accepts Doppler,
  which is what the user manual has been describing since v8.1.
- **The cells of a current record are no longer reported as overlapping
  qualifications.** A Doppler table is tidy - one row per record x depth cell -
  so `Site+Datetime` repeats once per cell by construction, and the database
  builder's overlap check, which keys on that pair, accused every row of the
  session (measured: 12 of 12 rows on a 4-record x 3-cell fixture). For a
  Doppler layout the check now keys on `Site+Datetime+Column+Cell`, so a
  genuine clash - the same cell of the same record qualified twice with
  different values - still warns, and the warning names the key it used. The
  Seaguard and HOBO layouts are untouched.

- **The current panels are put on screen, not only written to disk.** Every
  other panel family ends in `plt.show()`; the four Doppler panels were saved
  as SVGs and closed, so *Generate panels* looked like it had done nothing -
  the files were there, in `<output>/DatabaseView/<site> (current)/`, and only
  the log line said so. Showing is now the caller's choice: the Visualization
  tab shows them, while the qualification and the batch drivers keep writing
  the same files silently.
- **'Fixed scale' works on a Doppler database.** It is the one display option
  that applies to the current panels - it makes every heatmap share one speed
  color scale, so sites and years compare 1:1 - and it was being enabled by the
  data-type logic and disabled again, two calls later, by the gate that asks
  whether a panel checkbox is selected. A Doppler database has no panel
  checkbox by construction, so the whole Visualization settings box came up
  dead.

## Verification

- Self-test suite **54/54** (one new: the Doppler database keeps its 12 cell
  rows without an overlap warning, and a real cell clash still warns), ruff
  clean.
- The visualization fixes were measured on the operator's own qualified DCPS
  file, driving the real Step 2 outside the interface: *Fixed scale* goes from
  `disabled` to `normal`, and *Generate panels* writes the same four SVGs
  before and after. The panels appearing ON SCREEN was not verified this way -
  the probe runs on a non-interactive backend, where `plt.show()` does nothing.
