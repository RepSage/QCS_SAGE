1. Introdução

O QCS (Quality Control System) é uma solução completa para qualificação e visualização de dados oceanográficos de duas famílias de instrumentos: Seaguard/TSCP (temperatura, salinidade, condutividade, pressão, O₂, pH, clorofila, turbidez — perfis e fundeios) e, desde a v4.0, HOBO Pendant (temperatura e luz — ver seção 9). Este manual cobre todos os aspectos do sistema, desde a instalação até operações avançadas.

2. Instalação

Requisitos Mínimos

  • Windows 10 ou superior (64-bit)
  • Python (recomenda-se o Anaconda) com os pacotes do arquivo sourceCode/requirements.txt: numpy, pandas, matplotlib, scipy, openpyxl e gsw
  • sv-ttk (opcional, incluído no requirements.txt): tema visual "Sun Valley" (aparência do Windows 11, com modo claro/escuro). Sem ele, a interface usa o visual clássico — nada deixa de funcionar.

Novidade (v4.0): interface modernizada com modo escuro (interruptor no cabeçalho das janelas, preferência lembrada entre sessões), texto nítido em telas de alta resolução e um painel "Execution log" nas janelas principais, que mostra o progresso, avisos e erros de cada execução com cores por severidade.

Instalação Básica

O QCS roda diretamente a partir dos scripts Python (não há mais executáveis). Para preparar:

  1. Obtenha a pasta do projeto (contendo a subpasta sourceCode e os atalhos .bat)
  2. Instale as dependências, executando no terminal: 
    python -m pip install -r sourceCode/requirements.txt
  3. Para qualificar dados, abra QCS - Qualificacao de Dados.bat
  4. Para visualizar dados, abra QCS - Visualizacao de Dados.bat

Uma janela de terminal abre junto e mostra o progresso; ela fecha sozinha ao encerrar o programa (permanece aberta apenas se ocorrer um erro, para que a mensagem possa ser lida).

5. Flags de Qualificação

Estrutura das Flags

Cada dado recebe uma string de flags no formato [TEST1][TEST2]...[TESTN], onde cada teste é representado por um dígito:

Código Significado Descrição
1 GOOD_DATA Dado aprovado no teste
2 UNKNOWN Teste não pôde ser aplicado (dados insuficientes)
3 SUSPECT Dado suspeito (reprovado com margem)
4 BAD_DATA Dado reprovado no teste
5 DISMISSED Teste foi desativado pelo usuário
9 MISSING Dado faltante/NaN

Construção das Flags

  • Os testes são aplicados sequencialmente
  • Cada teste adiciona seu código ao final da string de flags
  • A ordem dos testes é fixa (faixa do sensor → faixa ambiental → spikes → taxa de variação → linha plana → gradiente vertical e inversão de densidade, estes dois apenas para perfis → janela de uso da luz, apenas para HOBO)
  • Flags são acumulativas - um dado pode ter múltiplos códigos
  • A correspondência exata posição → teste → variável é gravada no arquivo QCS_flag_legend.csv, gerado junto com cada qualificação (v4.0)

Exemplo

Flag 1942 significa:

  • 1: Aprovado no primeiro teste (sensor range)
  • 9: Dado faltante no segundo teste
  • 4: Reprovado no terceiro teste
  • 2: Teste desconhecido no quarto teste

Colunas Flag_ por variável (v4.0)

Além da string completa Flag, o arquivo qualificado traz uma coluna-resumo por variável (Flag_T, Flag_S, Flag_C, ..., Flag_lux nos arquivos HOBO), com a pior flag da variável naquela linha (prioridade 4 > 3 > 9 > 1 > 2 > 5). Assim não é preciso decodificar a string posição a posição para filtrar dados por qualidade — por exemplo, manter só as linhas com Flag_T <= 2 em uma análise de temperatura.

6. Gerenciamento de Configurações

Todos os critérios de qualidade (testes ligados/desligados, parâmetros e fatores por variável) são ajustados na janela Settings, aberta pelo botão Settings na janela principal. As escolhas ficam salvas automaticamente entre sessões.

Mudança na v4.0: os antigos Export Settings (exportar .json) e Config File (importar .json) foram removidos da interface — a configuração passa a ser feita inteiramente na janela Settings. As preferências continuam sendo salvas automaticamente no arquivo qcs_user_settings.json (gerado pelo programa, não versionado).

Restaurar padrões

A janela de Settings tem um botão "Reset to Defaults" que volta todos os critérios aos padrões da versão instalada. Valores inválidos digitados nos campos são listados em um aviso, em vez de ignorados em silêncio.

Atenção ao atualizar de versões antigas: por causa do controle de versão das preferências, ao rodar a v4.0 pela primeira vez os critérios de qualidade salvos da v3.2.1 são substituídos pelos padrões atuais (comportamento intencional — os critérios foram revisados). Caminhos de arquivos e últimas escolhas são preservados.

        "salinity sensor range": "ON",
        ...
    },
    "tsSettings": {
        "sensor_min_temp": -5,
        "sensor_max_temp": 35,

    }
}

7. Parâmetros de Configuração Detalhados

Nota (v3.1): time_window, fail_factor e susp_factor passaram a ser definidos por variável, na aba "Factors per Variable" da janela de Settings (uma linha por variável, colunas Fail / Susp / Time window). As descrições abaixo valem para cada variável.

time_window

Define a janela temporal para cálculos de desvio padrão em testes de spike e taxa de variação.

Formatos aceitos:

  • "WHOLE": Usa todo o dataset
  • "Xd": X dias (ex: "7d")
  • "Xh": X horas (ex: "24h")
  • "Xm": X minutos (ex: "30m")
  • "Xs": X segundos (ex: "300s")

Efeitos:

  • Janelas menores são mais sensíveis a variações locais
  • Janelas maiores suavizam variações mas podem mascarar anomalias
  • Para dados de fundeio longo, recomenda-se 1h-12h (a depender do intervalo amostral)
  • Para perfis, 1m-6m é geralmente adequado

fail_factor e susp_factor

Multiplicadores do desvio para classificação de dados. Desde a v4.0, a referência dos testes de spike e taxa de variação é um desvio robusto (1,4826 × MAD, o desvio absoluto mediano): o próprio valor espúrio não infla mais o limiar que deveria detectá-lo. Onde o MAD degenera (série quase constante), o cálculo recai no desvio padrão comum.

Comportamento:

  • fail_factor > susp_factor (tipicamente 3 e 2.5)
  • Valores altos reduzem falsos positivos mas podem deixar passar erros
  • Valores baixos aumentam sensibilidade mas também falsos positivos
  • Para dados ruidosos, aumentar ambos em 0.5-1.0
  • Para dados muito estáveis, pode reduzir em 0.5

Parâmetros da janela de luz do HOBO (lux_*)

Na aba Parameters da janela de Settings, os parâmetros com prefixo lux_ controlam o teste de incrustação da luz (apenas HOBO — ver seção 8):

  • lux_baseline_days: quantos dias iniciais definem o baseline de água limpa (maior pico diário de luz nesse período)
  • lux_cutoff_frac: fração do baseline abaixo da qual o pico diário indica incrustação
  • lux_sustain_days: por quantos dias consecutivos o pico precisa ficar abaixo do limiar para confirmar o corte

Os valores usados ficam escritos no próprio gráfico QCS_light_window.svg, no log e no QCS_test_report.csv — o corte é sempre rastreável.

8. Testes de Qualificação

Fluxo de Processamento

  1. Pré-processamento (correções de unidades, GMT-3)
  2. Testes de Faixa (sensor e ambiental)
  3. Testes de Spike
  4. Testes de Taxa de Variação
  5. Testes de Linha Plana
  6. (Para perfis) Testes de Gradiente Vertical e Inversão de Densidade
  7. (Para HOBO) Janela de uso da luz (incrustação)
  8. Geração de saídas

O log anuncia o pipeline em 5 estágios (leitura → pré-processamento → testes → saída/relatórios → gráficos), o que facilita localizar onde uma execução falhou.

Ordem Sequencial dos Testes de Qualificação (v4.0)

  1. Testes de Faixa do Sensor — reprovação vira BAD (4) (valor fisicamente impossível para o sensor)
    • Temperatura, Salinidade, Condutividade, Pressão, Oxigênio Dissolvido, pH, Clorofila, Turbidez
  2. Testes de Faixa Ambiental — reprovação vira SUSPECT (3) (alinhamento ao QARTOD: fora do envelope regional é suspeito, pois um evento extremo real é possível)
    • Temperatura, Salinidade, Condutividade, Pressão, pH, Clorofila, Oxigênio Dissolvido, Matéria Orgânica Dissolvida, Turbidez
  3. Testes de Spikes (Valores Espúrios) — método de 3 pontos
    • Temperatura, Salinidade, Condutividade, Pressão, pH, Clorofila, Oxigênio Dissolvido, Matéria Orgânica Dissolvida, Turbidez
  4. Testes de Taxa de Variação — reprovação vira no máximo SUSPECT (3) (QARTOD: variação rápida real existe)
    • Temperatura, Salinidade, Condutividade, Pressão
  5. Testes de Linha Plana (Flat Line)
    • Temperatura, Salinidade, Condutividade, Pressão
  6. Testes de Gradiente Vertical (Apenas para dados de perfil) — |ΔV/Δz| real em relação ao gradiente típico do perfil
    • Temperatura, Salinidade, Condutividade
  7. Teste de Inversão de Densidade (Apenas para dados de perfil)
    • Verifica a estabilidade da coluna d'água: a densidade potencial (calculada de T, S e pressão) não pode diminuir com a profundidade além de uma tolerância (configurável no Settings; padrão 0,03 kg/m³). Uma inversão indica um par temperatura/salinidade suspeito (flag 3) e implica ambas — não é descartado à força, só sai do resultado se "Remove Suspect Data" estiver ligado.
  8. Janela de uso da luz (Apenas para HOBO)
    • Teste de incrustação (biofouling) da luz — ver a seção Dados HOBO. Gera a posição de flag da luz (Flag_lux).

Arquivos HOBO: como o HOBO Pendant mede apenas temperatura e luz, somente os testes de temperatura da lista acima são executados, mais o teste da janela de luz. A string de flags fica curta e sem posições sem sentido.

Nota (v3.0): os critérios de qualificação foram revisados nesta versão para serem amplos e gerais (válidos de toda a costa brasileira, do Sul aos recifes amazônicos). O teste de spike passou a usar o método de 3 pontos (|V₂ − (V₁+V₃)/2|), e foi adicionado o teste de inversão de densidade para perfis. Por alterar os resultados da qualificação em relação às versões 2.x, é uma versão maior (v3.0).

Nota (v4.0): nova revisão que muda resultados em relação à v3.x: faixa ambiental e taxa de variação agora geram SUSPECT (não BAD), conforme o QARTOD; a referência de spike/taxa de variação passou a ser o desvio robusto (1,4826×MAD); o gradiente vertical passou a usar a profundidade de fato (|ΔV/Δz|); e diversas correções de defeitos (detalhadas no arquivo changelog/v4.0.md do projeto). Com "Remove Bad Data", valores fora do envelope ambiental não são mais removidos automaticamente — use "Remove Suspect Data" para o comportamento antigo.

Detalhes dos Testes

Cada teste gera logs detalhados no console, incluindo:

  • Tempo de execução
  • Número de dados reprovados
  • Percentual de reprovação

Seção: Junção de Arquivos no QCS_DatabaseView (motor build_database — v4.0)

Duas formas de montar o banco

Na janela Database Input Settings, primeiro escolha o Instrument (Seaguard ou HOBO — os dois nunca se misturam no mesmo banco) e então:

  1. Seleção manual: em "Database File(s)", selecione um ou vários arquivos qualificados (.csv ou .xlsx, em qualquer combinação) — eles são combinados, validados e deduplicados automaticamente; ou
  2. Join Data Files (pasta-mãe): marque a opção e aponte o "Input Path" para a pasta que contém as saídas do QCS. A varredura é recursiva: qualquer subpasta chamada exatamente QCS qualified tscp data (Seaguard) ou QCS qualified hobo data (HOBO) é encontrada, em qualquer nível.

Estrutura de pastas (exemplo para o modo Join)

Dados_Completos/
├── Camp1/
│   └── QCS qualified tscp data/
│       └── dados_camp1.csv
├── Camp2/
│   └── QCS qualified tscp data/
│       └── dados_camp2.xlsx
└── Camp3/
    └── QCS qualified tscp data/
        └── dados_camp3.csv

O que o motor de unificação faz

  • Valida o layout de cada arquivo (exige as colunas Datetime e Site) e detecta se é Seaguard ou HOBO — misturar tipos é recusado com mensagem clara.
  • Ignora os arquivos de relatório (tudo que começa com QCS_: report, stat, flag legend etc.) — só dados entram no banco.
  • Descarta duplicatas exatas (mesmo site, horário e valores), mantendo a primeira ocorrência e avisando no log; sobreposições com valores diferentes (mesmo site+horário vindos de arquivos distintos) são mantidas e reportadas com a lista dos arquivos envolvidos, para o operador decidir.
  • Adiciona a coluna Source file (de qual arquivo veio cada linha — proveniência) e ordena por Site + Datetime.
  • Mostra no log da janela de visualização um sumário por site (número de linhas e período coberto).

Se "Join Data Files" estiver marcado, o banco unificado também é salvo como .xlsx (com o nome do campo "Output Name") na pasta DatabaseView dentro do Output Path, para reutilização.

9. Dados HOBO (Temperatura e Luz)

Desde a v4.0 o QCS qualifica e visualiza dados dos loggers HOBO Pendant (Temperatura/Luz), além dos Seaguard. Selecione Input Type = HOBO na janela principal e aponte para a exportação do HOBOware.

Leitura dos arquivos

  • Aceita as exportações .xlsx e .csv do HOBOware, com cabeçalhos em português ou inglês (a linha de cabeçalho e o delimitador são detectados automaticamente; acentuação quebrada é tolerada).
  • Unidade da luz automática: lux é usado diretamente; lum/ft² (foot-candle) é convertido para lux (×10,7639). A saída é sempre em lux.
  • Janela de deployment pelos eventos do logger (Acoplador Ligado/Desligado, Parado, Fim do Ficheiro): linhas fora do período em água e linhas só-de-evento são descartadas, com registro no log. Leituras fora d'água nas pontas também são cortadas por salto de temperatura (parâmetro hobo_edge_temp_tol, com salvaguarda de não remover mais de 10% da série).
  • Zero de luz à noite é valor válido (nunca vira faltante); negativos viram 0.

Qualificação

Rodam os testes de temperatura aplicáveis a fundeio (faixa do sensor e ambiental, spike, taxa de variação e linha plana — gerando Flag_T) e o teste exclusivo do HOBO:

Janela de uso da luz (teste de incrustação)

Com o sensor no mar, organismos incrustantes vão cobrindo o logger e a luz medida decai — a partir de um ponto, ela deixa de ser confiável. O teste identifica esse ponto:

  1. O baseline de água limpa é o maior pico diário de luz dos primeiros lux_baseline_days dias;
  2. A luz vira SUSPECT (3) — o valor é mantido, não apagado — a partir do dia em que o pico diário fica abaixo de lux_cutoff_frac × baseline por lux_sustain_days dias consecutivos;
  3. Se depois do corte a luz ainda alcançar o limiar em boa parte dos dias (~20%+), um aviso indica que a queda não é permanente (possível limpeza do sensor, múltiplos deployments no mesmo arquivo ou período nublado) — revise.

Revisão interativa: antes de aplicar, o programa mostra o envelope diário da luz com o corte proposto — clique move a data do corte, a tecla N remove o corte, Enter/fechar confirma. O gráfico final é salvo como QCS_light_window.svg na pasta de saída, com os parâmetros usados escritos nele.

Limitação: o teste identifica um corte por arquivo. Se o sensor foi limpo e voltou à água no mesmo arquivo, o aviso de recuperação vai disparar — o recomendado é qualificar cada deployment (entre limpezas) como um arquivo separado.

Saída

A planilha qualificada HOBO contém apenas as variáveis medidas + metadados: Sample number, Datetime, Temperature (degC), Luminosity (lux), Expedition, Site, Battery voltage (V), Flag, Flag_T, Flag_lux, QCS version. Ela é salva na subpasta QCS qualified hobo data (a do Seaguard permanece QCS qualified tscp data). Planilhas HOBO e Seaguard nunca são combinadas no mesmo banco.

Para visualizar bancos HOBO (painéis dedicados de temperatura e luz com a janela de incrustação sombreada), veja a seção 11.

Conteúdo dos Arquivos

  • Arquivo Qualificado:
    • Todos os dados brutos (exceto o que "Remove Bad/Suspect Data" apagar)
    • Coluna "Flag" (string completa) e colunas Flag_T, Flag_S, ... por variável (pior flag da linha — v4.0)
    • Metadados (local, versão QCS). Latitude/Longitude não são gravadas (layout de colunas idêntico entre planilhas)
  • Relatório (QCS_report.csv):
    • Contagens bad/suspect/missing das 9 variáveis
    • Checagens de timestamp (retrocessos, duplicados, lacunas grandes)
    • "Valid" desconta linhas com dado ruim em qualquer variável
  • Relatório por teste (QCS_test_report.csv — v4.0):
    • Uma linha por teste executado: contagens de bom/suspeito/ruim/faltante, teste desligado e tempo de execução
  • Legenda de flags (QCS_flag_legend.csv — v4.0):
    • Posição da string de flags → teste → variável, e o significado dos códigos
  • Estatísticas (QCS_tscp_stat.csv):
    • Média, mediana, desvio padrão
    • Valores mínimos e máximos
    • Contagem de dados válidos (todas as variáveis presentes)
  • Janela de luz (QCS_light_window.svg — apenas HOBO, v4.0):
    • Envelope diário da luz com baseline, limiar e corte de incrustação aplicados, e os parâmetros usados escritos no gráfico

Painel Descrição Arquivo gerado

Nos eixos logarítmicos, leituras de luz igual a 0 (noite) não podem ser representadas e viram lacunas no gráfico; a quantidade omitida é informada no console. A escala fixa da luminosidade só é aplicada se o mínimo for maior que 0.

Configuração de Escalas

Controle avançado sobre as escalas dos gráficos através do painel "SCALE SETTINGS".

Escalas Fixas vs. Automáticas

Tipo Descrição Quando Usar
Escala Fixa Permite definir valores mínimos e máximos manuais para cada parâmetro
  • Comparação direta entre diferentes conjuntos de dados
  • Manter consistência visual entre gráficos
  • Destacar variações específicas em faixas conhecidas
Escala Automática O sistema ajusta automaticamente para mostrar todos os dados
  • Análise exploratória inicial
  • Quando a amplitude dos dados varia significativamente
  • Para visualizar a distribuição completa dos dados

Como Configurar Escalas Fixas

  1. Marque a opção "Fixed Scale" na seção de visualização
  2. Selecione os parâmetros desejados na seção "Select Parameters"
  3. Para cada parâmetro selecionado:
    • Digite o valor mínimo no campo correspondente na coluna "Min Value"
    • Digite o valor máximo no campo correspondente na coluna "Max Value"
  4. Salve as configurações com "Save View Settings"

Dica: Os campos de escala só ficam habilitados quando:

  1. A opção "Fixed Scale" está marcada
  2. O parâmetro correspondente está selecionado
  3. Pelo menos um painel de visualização está ativo

Filtros e Seleção de Dados

O sistema oferece múltiplas opções para focar em subconjuntos específicos dos dados:

Filtro Temporal

  • Por Ano: Digite um ano específico no campo "Filter by Year"
  • Por Data/Hora: Utilize a ordenação cronológica ("Sort by Time" na janela de entrada)

Filtro Espacial

  • Selecione locais específicos na lista "Filter by Site"
  • Para perfis, as coordenadas podem ser usadas no Diagrama T-S

Seleção de Parâmetros

  • Ative/desative parâmetros individualmente conforme necessidade analítica
  • Combine parâmetros relevantes para análise multivariada

Opções de Visualização Avançada

Opção Descrição Aplicação
Trend Lines Adiciona linhas de tendência polinomial Identificar padrões temporais
Show Data Points Exibe pontos individuais além da linha Visualizar densidade de dados
Fixed Scale Mantém escalas consistentes entre gráficos Comparação quantitativa

Atenção: Escalas fixas mal configuradas podem:

  • Ocultar variações importantes se a faixa for muito ampla
  • Cortar dados válidos se a faixa for muito estreita
  • Distorcer a visualização se mínimos/máximos estiverem invertidos
Sempre verifique os dados brutos antes de definir escalas fixas.

Fluxo de Trabalho Recomendado

  1. Comece com visualizações em escala automática para exploração inicial
  2. Identifique faixas típicas para cada parâmetro
  3. Aplique filtros para focar nos dados relevantes
  4. Configure escalas fixas para comparações sistemáticas
  5. Use linhas de tendência para identificar padrões
  6. Salve configurações úteis para reutilização

13. Execução a partir do Código-Fonte

A partir da versão 2.2, o QCS é executado diretamente pelos scripts Python — não há mais geração de executáveis (.exe). Isso significa que qualquer correção nos scripts vale imediatamente, sem necessidade de recompilar.

Requisitos

  • Python (recomenda-se o Anaconda)
  • Dependências do projeto instaladas (ver seção 2): numpy, pandas, matplotlib, scipy, openpyxl, gsw (e opcionalmente sv-ttk para o tema moderno)

Como executar

O modo recomendado é pelos atalhos .bat na pasta principal, que já chamam o Python correto. Alternativamente, na pasta sourceCode, é possível rodar os scripts diretamente:

python QCS_Main.py          # ferramenta de qualificacao
python QCS_DatabaseView.py  # ferramenta de visualizacao

Verificação rápida (autotestes)

Para conferir que as funções de qualificação estão íntegras após alguma alteração, execute na pasta sourceCode:

python QCS_SelfTest.py

14. Solução de Problemas

Problemas Comuns e Soluções

Problema Solução
Arquivo não carrega Verifique formato e codificação (usar UTF-8)
Testes não aplicados Confira se o nome do parâmetro bate com o esperado
Gráficos não gerados Verifique se dados possuem valores válidos
Erro de memória Reduza tamanho do dataset ou aumente memória
A janela de terminal fica aberta após o uso Indica que o programa terminou com erro; leia a mensagem exibida no terminal
"No year selected" ao gerar painéis Marque pelo menos um ano em "Filter by Year" e clique em "Save View Settings" novamente
"build_database: ..." ao montar o banco A mensagem indica o arquivo e o problema exato (coluna faltando, mistura de layouts Seaguard/HOBO etc.). Confira se o Instrument selecionado corresponde aos arquivos e se todos são saídas qualificadas do QCS
Diagrama T-S pulado Preencha Latitude e Longitude com valores válidos (graus decimais) — são obrigatórias para o T-S
Aviso de recuperação da luz após o corte (HOBO) O arquivo pode conter mais de um deployment (sensor limpo e devolvido à água); revise o corte na janela interativa ou qualifique cada deployment separadamente
